## 四、CK2：湖泊与河流的判据重做 ★★

### 4.1 我原来的判据是错的

用户先纠正名字（第一节 1.4），然后追问：

> 「为什么 CK2 有些湖泊是河流（里海），有些湖泊是海洋（罗布泊），这又是什么判据」

我原来那条：**在 `major_rivers` 名单里 → 河**；否则「四邻全陆地」→ 湖；其余 → 海。
于是里海成了河、罗布泊成了海。

### 4.2 用户让查原版怎么定义

> 「先看看原版游戏的名单是如何定义的吧」

实查三条，全部有据：

1. **`default.map` 里没有 `lakes` 这个键** ✗ —— 只有 `sea_zones`（区间）和 `major_rivers`。
2. **`major_rivers` 名单（113 个）不是"河"的名单** —— 它是**过河判定**那条河。
   真正的用途在 `adjacencies.csv`：那些 `major_river` 类型的邻接，第 4 列 `Through` 就是"从哪块水过去"。
3. **名单和穿越点对不上，而且差得很有规律**：

   | | 数量 | 是什么 |
   |---|---|---|
   | `major_rivers` 名单 | 113 | |
   | 真正当过 `major_river` 穿越点 | **91** | 全是真河段（莱茵 / 易北 / 伏尔加 / 多瑙…） |
   | 名单里但**从没当过穿越点** | **22** | **全是封闭水体**：里海 952、咸海 944、拉多加 958、奥涅加 997、伊尔门 1086、扎伊桑 1855、爱尔兰三湖 1990-1992… |
   | 当过穿越点却不在名单里 | **0** | 反向是空的 |

### 4.3 新判据（写在 `build_ck2.py`，注释里附了调研出处）

- **河段** = `major_rivers` ∩ `adjacencies.csv` 的 `major_river` 穿越点 → 91 个
  （`parse_river_segments()`）
- **湖** = 连不到大洋的水（`find_enclosed_lakes()`）：
  - 拓扑：四邻全是陆地的水块 = 封闭水体
  - 连通性：水块按邻接连起来，**只有两个分量贴着地图边缘**（地中海 164 块 / 印度洋 42 块）——
    那两个才是大洋；其余 29 个分量（里海那一坨 28 块 + 一堆单块）全是内陆水
- 结果：**海 132 · 湖 36 · 河 91**（改之前是 海 129 · 湖 17 · 河 113 ✗）

里海、咸海、罗布泊现在都是**湖** ✓；伏尔加 / 奥卡那串真河段仍是**河** ✓。

### 4.4 教训：**不能按名字猜，也不能按名单算**

- `Lake Ilmen`（伊尔门湖）**在** `major_rivers` 名单里 ✗
- `Atlantic`、`Kama`、`Lough Neagh` 这些名字对不上类别的，名单里也混着
- 反过来 `major_rivers` 之外当过穿越点的是 **0 个** —— 这条反向为空，是判据成立的证据

### 8.3 期间踩的八个坑（重做任何"按类别画边界"之前先读这段）

1. **类别图不能借用 `paintW / paintRows`** ✗✗ —— 那两个是"**每省一格**"的拍平尺寸
   （CK2 只有 2015×1），而类别图要按**像素坐标**采样 → 借用的后果是
   "整张图只有最上面 4 像素那一条有数据"，表现为**一条缝都画不出来**。
   必须自己算尺寸。
2. **不许用 4×4 块代表一格** ✗（用户明确否掉的）—— 块里混了陆地 / 水时，
   整块会被判成"更强的那个类"，于是**在纯水中间凭空生出一条假缝**、
   反而把真正的省界线压掉。
3. **类别的本质是两件 per-province 的事**：这一省是什么**种类** + 这一省**有没有主**。
   两个都是逐地块的量 → 按地块号一查就有，**不该铺按像素的图**（更不该用块）。
4. **两条通道不许在同一个地方各画一次** ✗ —— 我在同一条缝上跑了"类别通道"和
   老那条"按层"通道，后画的赢 → 水域那一档**怎么调都没反应**（"海域边界都归地区管了"）。
5. **GLSL 里常量 / 函数必须先声明后用** —— `const int MAXR` 在我那个新函数后面，
   报 `undeclared identifier`。
6. **着色器整段是 JS 模板字符串** ✗✗ —— **注释里不许出现反引号**，一个就截断整个文件。
   我在注释里写 `` `uBorderW` `` 就把 `gl.js` 截断了（测试当场炸在模块加载上）。
   改完着色器**一定跑一次** `node --check`。
7. **别按文本搜索做"按位置删"的大手术** ✗✗✗ —— 我写了几个"按内容找锚点再整段删"的脚本，
   它们撞上了**注释里提到的名字**（`this.clsDirty`、`texelFetch(uBorderClass, …)`），
   一次削掉几千行，把 `gl.js` 从 33 个类方法削到只剩 7 个。
   最后是拿一份完整快照**重建**才救回来的。
