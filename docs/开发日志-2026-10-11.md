## 三、三个值得记住的教训（这份日志的重点）

### ① "照着文档写断言"逮到了两个真 BUG

策划 4.5 条写着一句规矩：*覆盖同 id 时，省份数没变 → 涂色留着；变了 → 清掉并说明*。
我照着它两个方向各写了一条断言 —— **两边全红** ✗

查出来是同一族的错：仓库抛"已经导入过"这个错时，**只把旧记录挂上去了**：

| 界面里读的 | 实际值 | 后果 |
|---|---|---|
| `e.incoming` | 永远 `undefined` | `sameShape` 永远是 false → **每次覆盖都误判"省份数变了"，把玩家的涂色清掉** ✗ |
| `e.id` | 永远 `undefined` | 清的是 `pack:undefined` → **真该清的时候又清不掉** ✗ |

两个方向正好跟 README / 更新日志里承诺的**相反**：升个版本涂色没了、
换个省份数对不上的版本旧涂色却留着乱涂 ✓ 都是"看得见结果、想不到是这里"的那种。

**教训**：前面几笔验的都是"数据对不对"，这一笔验的是"界面对不对" —— 两条腿缺一条都不行 ✓
这种 bug 只要有一条**照着文档写的**断言就会露出来，所以"文档里的承诺"要一条条变成断言 ✓

### ② `hidden` 压不过 `display`：浮层关不掉（**玩家先发现的**）

廿九报的：「为什么一进来就有一个导入窗口还关不掉」——
那是导入地图包的「⋯」管理面板（导出备份 / 删除）✓

病因：`.pack-menu { display: flex }` **把我们自己的 `hidden` 属性压过去了** ✗
浏览器只给 `[hidden]` 一条 `display: none`（在 UA 样式表里），权重比类选择器低，
于是面板**永远显示**；而关闭按钮做的也正是设 `hidden`，所以按了等于没按 ✓
`.boot` 是满屏定位，它就正好浮在屏幕正中间 —— 跟玩家看到的一模一样。

**这个坑项目里踩过第二次了**：手机版那个改名窗（`mobile/mobile_css.txt` 里那句注释
"一进页面就杵在屏幕中间"）✗ 两次都是"记得给每个浮层补一条 `[hidden]`"靠人记，
所以就提到全局兜底了：`style.css` 顶部 `[hidden] { display: none !important; }` ✓

**教训**：**假 DOM 不做 CSS** —— 行为测得再细，这类"长得对不对劲"的 bug 一条都抓不到 ✓
这是这套自测结构的天花板，只能靠人点。所以这次补了一条**扫样式表**的断言
（兜底那条在不在），把能自动化的那一半先钉住 ✓

### ③ 需求理解偏差：我把"导入"想成了"版本更新"

我原来把 `manifest.id` 当主键：同一个包再导入，会**问要不要覆盖旧的那张** ✗
廿九要的是「导入的地图不覆盖之前的地图，而是新建一个地图，只是类型上遵循某个类型」。

**根子在策划阶段**：我在策划文档里写了一句"同 id = 同一张图的不同版本"——
那是**我自己加的设定**，需求里没有 ✗ 这种"我自己发明的规则"最该在动工前拿去确认一句 ✓

改法（第八笔）：库里分两层身份 —— 记录的键是**实例键**（第一份用作者 id，之后 `~2`、`~3`……），
`manifestId` 才是作者那个 id；界面 / 涂色键 / 删除 / 导出**全认实例键** ✓
唯一还会问一句的是"逐文件哈希全等的那一份"（多半是手滑重复导入），确认了也是新增，绝不替换。

**顺带的好处**：4.5 那套"覆盖时保留涂色"的逻辑**整个不需要了** ——
连同 ① 里那两个 bug 一起删掉。不是修好了，是**这条路没有了** ✓

## 六、还没做完 / 等廿九定

**① 两件只能在真浏览器里验的**（沙箱起不了无头浏览器，Edge 的 crashpad 被拒）
- 新界面的**长相**（导入入口 / 卡片 / ⋯ 面板 / 进度条 / 红字那几块的排版）
- `file://` 双击打开时 **IndexedDB 归哪个来源**（Chrome 和 Firefox 不一样；
  换目录或改名后看不到已导入的图是有可能的）→ 界面有「导出备份」当后路

**② 待定的一个产品问题：要不要把固定的那几套地图拆成"包"发布**

廿九问的「能否凭借这个新功能，压缩我们固定的五张地图」。
量下来的结果（用已打好的三个包校准过，误差 1% 内）：

| 地图 | 现在内嵌占 | 做成包 |
|---|---|---|
| CK3 | 3.13 MB | 2.35 MB |
| EU4 | 1.04 | 0.78 |
| EU4HD | 1.12 | 0.84 |
| HOI4 | 1.87 | 1.40 |
| HOI4 改边界 | 1.87 | 1.40 |
| V3 | 4.77 | 3.58 |
| EU5 | 5.12 | 3.84 |
| EU5 原尺寸 | 16.27 | 12.21 |
| **合计** | **35.18** | **26.40** |

- 差的那 8.8 MB 是 **base64 的税**（单文件是文本，二进制只能 base64）—— 不把数据搬出去就省不掉 ✓
- 而"壳"（HTML + CSS + 全部 JS）只有 **594 KB** → 全拆之后 HTML **0.6 MB**，是现在的 1/60
- 三条路：**A 全拆**（最省，但砸掉"一个文件双击即用、不联网"的卖点）·
  **B 两套都发**（老的照旧 + 另出 lite 版和 8 个包，包放 Release 附件）·
  **C 混合**（lite 里只内嵌最常用的一两张，其余走包）
- 建议先 B；要动的地方很少（`build_standalone.py` 加开关、**没地图时的引导页**、
  `check_standalone.js` 按变体验、一个循环打 8 个包）
- 另外：包和内嵌的同名图会同时出现两张卡（只增不改），得给内嵌那张认个身份或提示一句

## 七、接手的人从哪儿看起

```bash
# 想打一个地图包（作者视角）
python pack_map.py data_eu4 --id 我的图 --label "我的图" --author 我 --out 我的图.pdxmap

# 改完代码该跑的
node test_modes.js CK3                 # EU4 / EU4HD / HOI4 / VIC3 / EU5 同理
node tools/check_pack.js && node tools/check_import.js
python build_standalone.py && node tools/check_standalone.js
python mobile/build.py     && node tools/check_mobile.js
node tools/check_log.js
```

**六条别踩的**（都是今天花时间换来的）

1. **新加 js 文件要同时登记三处清单**：`build_standalone.py` 的 `MODULES`、
   `tools/lib/browser_stub.js` 的 `MODULES`、`test_modes.js` 里那份（顺序要一致）。
   漏一个的表现是"某个功能悄悄没了"，不是隔壁报错 ✗（今天踩了两回，现在有断言盯着）
2. **`packstore.js` 里只能写行首的静态 `import`** ✗ 动态导入在单文件版里会原样留在产物里，
   `file://` 下必炸（`check_standalone.js` 有一条断言扫这个字面写法）
3. **`.bin` 是两层压**（zip 一层 + 内部 zlib 一层）：长度要在**第二层**算，
   而 `manifest.files` 的 sha256 是**第一层**（zip 里那份）的 ✗ 搞反了所有包都会"哈希不对"
4. **浮层别靠"记得给 `[hidden]` 补一条"** —— 全局兜底已经加了，别删（有断言）
5. **`manifest.id` 不是主键** ✗ 导入只增不改，界面 / 涂色 / 删除 / 导出全认**实例键**
6. **校验器和 `pack_map.py` 的常量必须一致**（格式版本 / 必需文件 / 字段上限 / 体积上限）——
   `check_pack.js` 开头会读 Python 源码来对 ✓ 故意改坏试过，会红

**今天新增的两条"给未来的守卫"**，改代码时别当成累赘：
- 三份拍平清单必须互相对得上（`test_modes.js`）
- 样式表里 `[hidden]` 兜底必须在（`check_standalone.js`）
