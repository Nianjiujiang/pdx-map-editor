## 四、顺手逮到的那个真 bug（值得记）

轻量版一跑就露出来了：`data.js` 里

```js
let EMB_MAP = EMB ? (EMB.vanilla || EMB) : null;   // ✗ 空对象也是真值
```

轻量版的 `window.__CK3_EMBEDDED__` 是 `{maps:{}}` —— **空对象也是真值** ✗
于是它以为"有内嵌数据"，每次取字节都去解一份空数据，
报出来是 `atob` 的 "The string to be decoded is not correctly encoded" ✓

顺带还发现 `setDataDir()` 只清了 `PACK`、**没清 `EMB_MAP`** ——
"三个来源互斥"那条规矩（`data.js` 自己的注释里写着）漏了一个角 ✗

**教训**：这是"**零张**内嵌地图"这个新形态带出来的 ——
老代码里"有内嵌数据"隐含等于"至少有七张图"，一旦允许零张，
每一处 `if (EMB)` / `if (EMB_MAP)` 都得重新想一遍 ✓
（同类隐患扫过一遍：`availableMaps` 按 `EMB.maps` 的键数列卡，空的就是列不出来 ✓ 没问题）

## 五、删掉「头衔」那组死 UI（廿九点名的）

她说：「头衔那边的相关显示设置用不到了可以删掉了」。

我一开始还回了一句"那组是真接线的、删了 CK3 就没开关了" —— **是我看错了** ✗
我照的是代码里那句注释（"CK3 仍旧用「头衔」一组"），可那句**早就过时了**：
CK3 现在也有剧本层（1066 / 空白剧本 → `meta.eraDates` 两条），
而界面显示哪一组的判据正是"有没有年代层"：

```js
_tg.style.display = _hasEra ? 'none' : '';   // 头衔那组：没年代层才显示
```

于是**每一个模式**里 `_hasEra` 都成立 → 那组控件**永远是藏着的** = 纯死 UI ✓
她比代码注释清楚，这也说明代码里的注释是会骗人的 ✗

删掉的东西：`#titles-group` 那一整块（颜色 / 边界 / 名称 / 父级边界）、
`show-titles` / `show-border-title` / `show-labels` / `show-parent-border-ck3` 这四个 id、
它们的监听器、以及"按年代层收放"里管它的那两行 ✓

**运行时一点变化都没有** —— 它控的三样本来就由「势力 / 地区」每帧算出来写进 state：

```js
state.showTitles      = isPower ? showPowerColor  : showRegionColor;
state.showBorderTitle = editIsPower ? showPowerBorder : showRegionBorder;
state.showLabelsTitle = state.showRegionName;
```

顺手逮到两处"删 UI 忘了删引用"（真浏览器里会直接抛错 ✗，
假 DOM 却没反应 —— 它的 `getElementById` **找不到会现造一个** ✗✗）：
`$('title-group-label').textContent = g.entity` 和边界那对复选框的读取。
所以这次的守卫改成**扫源码**（`id="show-titles"` 在不在 index.html 里），
而不是问假 DOM"元素还在不在" —— 后者永远会回答"还在" ✓
