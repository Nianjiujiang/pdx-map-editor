## 0. 一句话结论

EU4 上「地名/国名乱码、显示 `P 5139`、地貌写 `#大泽山`、或落到英文」这一串毛病，
根子都在**读文件的范围太窄 + 编码判死 + 名字列没按 `#` 拆**。五处修完，
风云世纪两千年那张图从「满屏乱码」变成「全中文」，而且**荒地名字零坏项**。

## 1. 我改了哪四个地方

### ① 编码：UTF-8 优先，cp1252 兜底 —— `parsers/eu4/parser.py` 的 `read_text()`

原来**一律按 cp1252** 解（原版 EU4 确实如此）。可中文 mod 的 `definition.csv`
是 UTF-8，中文字节被当 cp1252 → `宋卡` 变 `å®‹å¡`，99 个省份全乱码。

```python
raw = path.read_bytes()
try:    return raw.decode("utf-8-sig")
except UnicodeDecodeError: return raw.decode("cp1252", errors="replace")
```

纯 ASCII 两者等价，**原版一个字节都不变**（实测 `Östergötland` 还是它）。
⚠ `history.py` 里另有一套 `latin-1` 直读，**我没动**（那是另一个文件族，没症状）。

### ② 本地化：整目录递归读 —— `build_eu4.py` 第 12 节

原来读名字是**手写 5 个顶层文件名**。可 mod 把整个省份名表放在
`localisation/replace/bu_prov_names_l_english.yml`（Paradox 的 `replace/` 覆盖机制）
→ 64 个省份查不到 → 退成 `humanize('p_5139')` = **`P 5139` 印在图上**。

改成 `E.read_loc_dir(LOC)`（它本来就递归、且按 `replace/` 后读覆盖）。
**实测：`P 编号` 占位 63 → 0，中文头衔名 7830 → 9103。**

### ③ 汉化目录探测：也要递归 —— `_hanhua_dirs()`

`zh` 那条路（水域 / 荒地名）只 glob 顶层 `*_l_english.yml`，同样漏掉 `replace/`。
→ `own` 没被收进来 → `_pick_hanhua` 跑去挑外面的纯汉化包（5913 条，没有 `PROV5xxx`）
→ 荒地名退成 `definition.csv` 的英文。

把 `own.glob(...)` 改成 `own.rglob(...)`。

### ④ 逐块荒地的名字 —— 🔴 **真凶已找到，两条补丁已删**（21:50 追写）

> **原文先说结论**：我当时在 `build_eu4.py` 末尾加了 `_fix_waste_names()`，
> 又在主流程里加了一段"伪头衔名字校正"，都是**在产物上把名字重写一遍**。
> 追了七八轮没定位到"是谁改回去的"，只好打补丁。
>
> **现在查清了：是三条上游 bug 叠出来的**，补丁全是在下游擦屁股。三条都修完，
> 两处补丁都成了空转（实测"改名 0 个"），**已连同函数一起删掉**。

**症状**：荒地节点名字两种坏法 ——
- `wl_3210` → `#大泽山`（`#` 是 EU4 "只当地名不上地图"的约定，被当名字印出来了）
- `wl_5067` → `Eastern Daba Mountains`（落回英文）

**三条真凶**（按链路顺序）：

**真凶 A —— `definition.csv` 的中文写在 `#` 后面，没拆**
`parsers/eu4/parser.py` 的 `parse_definition()` 原来整列照抄第 5 列。
可这个 mod 把中文塞在两个位置：
```
3210;255;203;198; #大泽山                                   ← 第 5 列
5067;225;221;146;Eastern Daba Mountains;x #大巴山（东）      ← 第 6 列
69;...;Ravensburg;x  #拉芬斯堡                               ← 第 6 列（273 个）
```
→ 748 个省份要么名字带井号、要么只剩英文。
新增 `_pick_def_name()`：**`#` 之后必须有汉字才取它** ✓
（原版 `Central Atlantic #1` 那种编号**原样保留** ✗ 实测 131 个全留住了 ✓
 `; #` 这种空占位返回空字符串 ✓ 不返回井号 ✓）

**真凶 B —— `patch_wasteland.py` 拿 `provinceNames` 覆盖了中文名** ⬅️ **最隐蔽的一条**
`eu4` 那一支按 `provinceNames[pid]` 写名字。可荒地块**不在省份层**里，
那一格常常只有英文（`Vistula Lagoon` 是波兰的维斯瓦潟湖，跟"喀尔巴阡山脉"根本不搭）
→ 一覆盖就把构建期按 `waste_names` 写好的中文盖掉 ✗
改法：**节点名已经是中文 → 让开** ✓ 一个字节都不动 ✓
（不是中文才补 ✓ 所以老包 / 别的语种行为不变 ✓）

> 为什么当初查不出来：`name_sink` 里一直是**对的**（打印过 ✓），
> 错在 `localize_names()` **之后**、`patch_wasteland()` 那一步。
> 中间隔了 5 次写盘，每次都可能改名字，所以"打印和成品矛盾"✓
> 现在有 `tools/check_eu4_encoding.js` 盯着（17 条 ✓ 见 §4）。

**真凶 C —— 逐块荒野 / 粗层片名的 `name_sink` 值带 `#` 前缀**
`build_tier_pieces.py` 里 `(waste_names or {}).get(pid) or label`，
`label` 是 `#wasteland` 那种 → `#` 串进名字里 ✗ 已 `lstrip("#")` ✓
粗层片名（`#wasteland_rg_0` → `#3737`）同样处理 ✓

**验尸结果**：
```

wl_3210 = 大泽山   wl_5067 = 大巴山   wl_3139 = 喀尔巴阡山脉
```

## 2. EU4 新增的两个参数（做 mod 地图用的）

`build_eu4.py`：

```bash

  --bookmarks <合并根>/common/bookmarks \
  --eras 867,1066,1444,1618,1789,1836,1936 \
```

配套：`parsers/eu4/parser.py` 新增 `parse_bookmarks(dir) -> [((y,m,d), 名字键)]`。

## 8. 合并了仓库来的 Safari 修复（PR #9）

**21:55 从 `origin/main` 合进来的**，文件跟 EU4 这条线**零重叠** ✓
（只碰 `web/js/packstore.js` / `web/js/data.js` / `tools/lib/browser_stub.js`）

**它修的是什么**：Safari 在隐私模式这类**临时存储**下，IndexedDB **不收 Blob**：
```
UnknownError: Error preparing Blob/File data to be stored in object store
```
同一个库存 ArrayBuffer / Uint8Array / 字符串都正常 ✓ **只有 Blob 不行** ✓
→ 用户报「iPad 导不进地图、整个工具用不了」（issue #3 ✓）
→ 而 Chrome / 桌面上一切正常 → 一直没被发现 ✗

**改法**：
- 写库前把 `blob` 统一转成 `ArrayBuffer` / `Uint8Array`（`putPack` 里 ✓
  **转换必须在开事务之前做完** ✗ 事务里除了 IDB 请求不许 `await` 别的 ✓）
- 读图那条路改成 `getFileBytes()`（直接取字节 ✓ 少一次整份拷贝 ✓
  省份 id 图动辄几百 MB，手机上少这一份就不容易爆 ✓）
- 老的 `getFile()` 保留（把字节包回 Blob ✓ 旧调用方一个字都不用改 ✓）
- **老库里存着的 Blob 仍然读得出来** ✓（升级不丢图 ✓）

**桩也一起改了**：`browser_stub.js` 的假 IndexedDB 现在**照 WebKit 的样子拒收 Blob** ✓
（以前什么都收 → 往库里写 Blob 这种在 Safari 上必炸的写法，自检里一路绿灯 ✗）
