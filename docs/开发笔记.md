# CK3 / EU4 / EU5 / HOI4 / V3 地图编辑器

拿《十字军之王 III》《欧陆风云 IV》《钢铁雄心 IV》《维多利亚 3》的真实地图数据当底子，
看地块属于哪一级行政区、把颜色吸过来、再刷到别的地方。CK3 / EU4 改完直接导出成
能丢进游戏的 mod；HOI4 没有这条路（原因见下）。

启动时先选一张地图（CK3 原版 / EU4 原版 / EU5 原版 / EU5 原尺寸 / V3 原版 / HOI4 原版），
四个游戏除了叫法不一样，渲染和操作**完全共用**；层级数也按数据来
（CK3/EU4/HOI4 是 5 层，V3 是 4 层）。

**换一套地图**靠 `--map` / `--mapdir` 指过去（见下）：那套图自己的
`provinces.bmp` 和 area / region / continent / positions 优先用它的，
它没带的文件（比如 `superregion.txt`）回退到游戏本体 ✓ —— 一个文件一个文件地
"覆盖目录优先、本体兜底"。这样换分辨率、换重画过的边界都不用改代码。

> 自己拆出来的地图里，`definition.csv` 偶尔有编码坏掉的名字（`Östergötland` →
> `\uFFFDsterg\uFFFDtland` 这种）。烤缓存时会拿本体的名字补回来，
> 免得导出 mod 时把这个坏名字写进去。

**HOI4** 是第三套，五层是 `1936 / 1939 / 战略 / 地区 / 省份` ——
前两层是年份归属，后三层是战略区（strategic region）、州（state）、省份。
它省事的地方是**官方自带简体中文**（`localisation/simp_chinese`，UTF-8 BOM），
不用装汉化 mod；费事的地方是**省份自己在游戏里没有名字**，详见下面「HOI4 这边」。

## 怎么跑

### 方式一：双击单文件（最省事）

先用 Python 烤一次缓存：

```bash
python build_data.py             # CK3 原版，约 4 秒
python build_data.py --map <另一套图的 provinces.png> --out data_xxx --label "自定标签"
python build_eu4.py              # EU4 原版，约 1 秒
python build_eu4.py --mapdir <另一套图的 map 目录> --out data_xxx --label "自定标签"
python build_hoi4.py             # HOI4 原版，约 2 秒
python build_vic3.py             # V3 原版，约 5 秒
python build_standalone.py       # 打成自包含 HTML，约 5 秒
patch_wasteland.py  荒地的事后加工（幂等；构建器收尾会自动调它）
```

然后**双击**项目里的 `pdx-map-editor.html` 就能用 —— 约 38 MB，网页、脚本和
八套地图的数据全在那一个文件里。可以直接拷走、发给别人。

> 为什么必须这么做：`file://` 协议下浏览器会拦掉 `fetch` 和 ES module，所以
> 直接双击 `web/index.html` 是打不开的。单文件版把脚本拍平成普通代码、数据用
> base64 内嵌，绕开了这两个限制。

### 方式二：本地服务

```bash
python build_data.py
python build_eu4.py
python server.py                 # 起服务并自动打开浏览器
```

也可以直接双击 `启动.bat`（它会自己检查 Python 和 Pillow）。

浏览器打开 <http://127.0.0.1:8777/>。

游戏装在默认位置的话会自己找到（Steam 注册表 + `libraryfolders.vdf` 都翻了），
找不到就手动指：

```bash
python build_data.py --ck3 "D:\Steam\steamapps\common\Crusader Kings III"
python build_eu4.py  --eu4 "D:\Steam\steamapps\common\Europa Universalis IV"
```

换游戏版本、或者加了 mod 之后，重跑对应的 build 脚本；用了单文件版的话
再补一次 `build_standalone.py`。

## 怎么用

**看。** 鼠标停在任何地块上，左边会列出它从上到下的完整归属，每一层都带颜色方块。

| 层级 | CK3 | EU4 | HOI4 | V3 |
|---|---|---|---|---|
| 0 | 帝国 `e_` | **1444 年的归属** | **1936 年的归属**（风暴前夜） | **1836 年的归属** |
| 1 | 王国 `k_` | **1618 年的归属** | **1939 年的归属**（闪电战） | 战略区 `region_x` |
| 2 | 公爵领 `d_` | **1800 年的归属** | 战略区 `STRATEGICREGION_1` | 州 `STATE_X` |
| 3 | 伯爵领 `c_` | 地区 `_area` | 州 `STATE_1` | 省份 `p_<id>` |
| 4 | 男爵领 `b_` | 省份 `p_<id>` | 省份 `p_<id>` | — |

**EU4 的顶部三层是三个年份的归属地图**（1444.11.11 / 1618.1.1 / 1800.1.1），
按那年谁占了这块地来上色，颜色就是那个国家的国旗色（`common/countries`）。
原来的大洲/大区/区域不单独成层了 —— 想换回去：`python build_eu4.py --no-history`。

**在年份视图里，顶部「视图」那一排兼作粒度开关**，没有另开一排。
一句话：**年份和细层级是一对，年份出配色，细层级出边界和笔刷；按一下就配上，再按一下就拆开。**

| 动作 | 结果 |
|---|---|
| 年份视图里按 **地区** / **省份** | 配上：配色还是那年，边界和笔刷跟到那一级 |
| **再按一下同一个细层级** | 拆开，回到那一年的整国粒度 |
| 在**地区 / 省份视图**上按一个年份（比如省份模式按 1618） | 配上：1618 配色 + 省份粒度 |
| **再按一下同一个年份** | 拆开，退回省份视图 |
| 配对状态下按另一个年份 | 只换配色，粒度不动 |

亮起来分两档：**视图**是金色，**粒度**是弱一档的蓝，两个一起亮的时候一眼能分出主次。

**取色和涂色是两回事**：取色（吸管 W、右键）永远取**画面上这一刻的颜色**，也就是
**视图那一层** —— 开着 1444 + 省份粒度，吸管吸到的是 1444 那个国家的国色
（实测 `8,82,165`），不是省份原色（`0,36,128`）；涂色和还原才按**粒度**落笔，
只动那一个省份。悬停高亮跟着粒度走，亮起来的那块正好就是点下去会涂到的那块。

实现上就靠渲染器多一个 `uEditTier`：颜色查 `uTier`、边界和悬停查 `uEditTier`，
平时两者恒等，配成一对才分开（`gl.js` 里 `tidAt` 和 `colorOfPid` 是两条路）。
悬停卡片上点更细的那两行、或者在搜索里点地区/省份，走的是 `gotoLevel()` ——
"点谁就按谁编辑"，不配对也不拆对。

> 同一个国家在三个年份是**各自独立的节点**（`1444_SWE` / `1618_SWE` / `1800_SWE`）。
> 共用一个的话，涂 1444 的瑞典会把 1618、1800 的瑞典一起涂了 —— 涂色刷的是
> "这个节点在它那一层的地盘"，一个节点只能属于一层。

**CK3 的法理按 1066 年算。** `common/landed_titles` 里那套嵌套只是"默认"法理，
`history/titles` 里带日期的 `de_jure_liege` 才是各剧本的改动 —— 把 1066 之前的
全盖上去，15 个头衔的父级跟骨架不一样。差别是实打实的历史：诺曼征服之后
赫里福德从威尔士的 `d_powys` 归到英格兰的 `d_hereford`，巴伐利亚/波希米亚/
弗里斯兰 962 年之后归了 `e_hre`。换别的年份：`--dejure-year 867`。

**取色。** 按 `W` 切到吸管，点一块地就把它**此刻显示的颜色**吸成画笔色（所以吸到的
可能是你自己涂的色，而不只是游戏原色）。右键点地图也能取色，并且顺手切到涂色。
也可以直接点左边列表里的任意一行 —— 那会同时切到那一层并取色。

**涂色。** 按 `E` 切到涂色，调好画笔颜色，点下去。按住拖动能连着刷一片。
「标记」那一栏是这支笔的名字，涂完色块上标的字就是它 —— 取色时会自动填成你点的那块地。
改了「标记」再涂一遍同一块地，标记就换掉了（**颜色一样也照涂** ——
判断"这块不用再涂"要看颜色**和**标记，只看颜色的话标记永远改不掉）。

**涂色是新建一块「玩家填色区」，不改游戏原有的配色。** 头衔自己的颜色表一个字都不动，
填的色只活在**手绘层**里（一个省份一格）；所以关掉「填色·颜色」之后，底色还是游戏原色，
而不是被你改过的那份。导出的 mod 用填色区现算，也不动原表。

**色块的名字。** 关掉「头衔·颜色」之后（只看自己涂的东西那种用法），地名标的是
**手绘色块**的名字，不是行政区的名字。

一块的定义是**同色 + 同标记**，两者有一个不同就是两块。同一个「同色同标记」组里
可能有好几块互不相连的地方（一整片主色块 + 一堆沿海小岛），这种**只留面积最大的
那一块**露名字，标在它自己的**几何中心** —— 免得满屏都是同一个小岛的标签。

> 分组键是「同色 + 同标记」，不是只看标记 —— 同一个标记用在两种颜色上是两组，
> 各留各的最大块。早先只按标记分，会把其中一块吞掉。

> 两块**相邻且同色**时，名字可能贴得很近（小地块上字比地还宽，就会叠在一起）。
> 想让它们分开，给两块不同的标记 —— 那就是两块，各标各的。

> 注意颜色的粒度是**整块行政区**，不是像素。给一个伯爵领上色，它下面所有男爵领
> 地块会一起变 —— 因为游戏本身就是这么存颜色的。想让单个男爵领有独立颜色，
> 就先切到男爵领视图再涂。

**还原。** 按 `R`，点一块地恢复成游戏原来的颜色。工具栏的「还原」是一键清空全部改动。

**导出 mod。** 工具栏右边那个按钮，CK3 和 EU4 导出的东西完全不同（HOI4 没有这条路，按钮是收起来的）：

- **CK3** → 几个 `common/landed_titles/*.txt`，写上改过的颜色。解压到
  `文档\Paradox Interactive\Crusader Kings III\mod\` 下面就能在启动器里勾选。
  游戏里同名的头衔块是**按块覆盖**的，所以导出文件里只写了颜色那几个字段。
- **EU4** → `map/provinces.bmp` + `map/definition.csv`。因为 EU4 的省份颜色
  **根本不在文本文件里**——颜色就是省份的身份，那张 BMP 就是定义表，跟 definition.csv
  一一对应。所以导出的是"按你涂的颜色重画一遍省份图"，两个文件必须成对覆盖。
  解压到 `文档\Paradox Interactive\Europa Universalis IV\mod\` 下面。
  如果涂出了重复颜色会提示你 —— EU4 靠颜色认省份，撞色会认错。

### 快捷键

| 键 | 作用 |
|---|---|
| `1` – `5` | 切换五个层级视图 |
| `Q` `W` `E` `R` | 查看 / 吸管（右键也行）/ 涂色 / 还原 |
| `Ctrl+Z` `Ctrl+Y` | 撤销 / 重做 |
| `F` | 缩回全图 |
| `方向键` | 推视角（按住 `Shift` 步子大一点） |
| `Esc` | 清空搜索 |

滚轮缩放（对着鼠标位置）、拖拽平移。把导出的 JSON 工程拖进窗口可以直接导入。

**搜索定位**（右侧那一栏）：中文名、英文名、key 都搜得到（`英格兰` / `England` /
`k_england` 是同一个结果），结果按地盘大小排序，**点一下**就跳过去。
跳过去的**缩放是按地盘算的**（`searchJumpScale()`）：小男爵领会凑近到看得清，
帝国会退远到能看全 —— 以前这里是写死的 0.35，搜到一块小地也停在全图视角，等于没定位。

**三套地图的涂色互不互通。** CK3 / EU4 / HOI4 的省份编号是三套完全无关的编号，
存档分开放在 `ck3-map-editor/v1` 和 `eu4-map-editor/v1`，各画各的。

## 数据从哪来

### CK3

全部读自安装目录的 `game/`：

| 用途 | 文件 |
|---|---|
| 地块边界（9216×4608 的颜色图） | `map_data/provinces.png` |
| 地块编号与内部名 | `map_data/definition.csv` |
| 头衔层级、颜色、省份归属 | `common/landed_titles/*.txt` |
| 中文名 | `localization/simp_chinese/titles_l_simp_chinese.yml` |

几个从数据里摸出来的事实，代码是照这些写的：

- `provinces.png` 不是调色板索引图。它每个像素的 RGB **直接等于**
  `definition.csv` 第三列登记的颜色，靠颜色查表反推地块编号。
- 头衔的父子关系是**靠嵌套**表达的 —— `e_x = { k_y = { d_z = { c_w = { b_v = { province = 1 } } } } }`。
  解析时非头衔的块（`cultural_names`、`can_create` 之类）也必须压栈，否则一个 `}`
  就能把整棵头衔链弹飞。
- 头衔名里大量是 `$k_lotharingia$` 这样的变量引用，要展开。
- 本地化行尾常跟着 `#注释`，正则不能锚定行尾，不然东亚那一大片头衔会整批漏掉。
- 颜色有三种写法：`{ r g b }`、`rgb { ... }`、`hsv { ... }`。最后这种是"前缀 + 块"，
  解析器如果只认 `{` 开头的值，`hsv` 后面那个 `{` 会被当成新键，而它的 `}` 就会跑去
  闭合外层头衔 —— **从那一行起整棵树错位**（拜占庭帝国会变成没有子级的空壳，
  苏格兰、爱尔兰、安纳托利亚这些王国全掉到顶层）。
- 头衔 key 里会出现连字符（`e_caspian-pontic_steppe`）。正则漏掉 `-` 的话，
  这个帝国连同它下面的 7 个草原王国会一起消失。
- 缺就是缺，**不要替它编**。有些王国（威尼斯）法理上确实不属于任何帝国，
  如果拿它下面某一层的头衔去填帝国层，就会凭空造出"威尼斯帝国"这种关系。

### EU4

读自安装目录的 `map/`（和 `localisation/`）：

| 用途 | 文件 |
|---|---|
| 地块边界（5632×2048 的 24 位 BMP） | `map/provinces.bmp` |
| 地块编号（1…4941）与原色、名字 | `map/definition.csv` |
| 省份 → 地区 | `map/area.txt` |
| 地区 → 区域 | `map/region.txt` |
| 区域 → 大区 | `map/superregion.txt` |
| 省份 → 大洲 | `map/continent.txt` |
| **历代归属**（1444/1618/1800 三层） | `history/provinces/*.txt` |
| **国家国旗色** | `common/country_tags/*.txt` → `common/countries/*.txt` |
| 海 / 湖 / 随机新世界 | `map/default.map` |
| 名字（只有英法德西，没有中文） | `localisation/prov_names_l_english.yml`、`countries_l_english.yml` 等 |
| **中文名**（如果有装汉化 mod） | 汉化 mod 的 `localisation/*_l_english.yml`，见下面「汉化 mod 的双字节编码」 |

EU4 这边的坑：

- **历代归属**写在 `history/provinces/<id> - <名字>.txt` 里，格式是"先一个无日期段，
  再一串带日期的改动"：`owner = BYZ` … `1453.5.29 = { owner = TUR }`。
  所以某年的归属 = 日期不晚于那年的最后一条，一条都没有就用开头那段
  （那就是 1444 剧本的状态）。解析必须走**块**解析 —— 按行扫会被
  `add_permanent_province_modifier = { ... }` 里形似 owner 的键骗到。
- `definition.csv` 是**分号分隔、cp1252 编码**的。用 utf-8 读会把
  `Östergötland` 读成乱码。
- `area.txt` / `region.txt` 里每个分组**都夹着 `color = { r g b }`**（地区自带配色）。
  数省份 id 的时候不先把 color 块挖掉，118 / 99 / 151 这些色值就会被当成省份号，
  于是"罗马同时属于布列塔尼、布拉班特和拉齐奥"这种鬼话就出来了。
  挖掉之后真实冲突只剩 1 个：4648 在 `durango_area` 里写了两遍。
- 大洲在 `continent.txt` 里是**直接挂在省份上**的，不经过大区。所以"大区属于哪个洲"
  只能拿成员的省份投票。近东、波斯这种横跨欧亚的大区本来就不该有唯一答案 ——
  编辑器让 `titlemap` 的大洲那一行**按省份各自取真实值**，投票结果只用来给大区
  定父级（跨洲的会记进 `meta.splitSuperregions`）。**现在默认用三个年份视图，
  这条路只在 `--no-history` 下才走。**
- `positions.txt` 里那组主城点是**给 3D 单位站位用的**，不是标签锚点，现在不读了。
  标注位置一律用几何中心（见下面「地名标注在哪」）。
- `provinces.bmp` 里其实**有 100% 的像素都能对上 definition.csv**，但 definition.csv
  里有 1016 个省份（id 3004–4019）在图上一个像素都没有 —— 那些是留给随机新世界的。

### 地名标注在哪

| | 标在哪 |
|---|---|
| **EU4**（五个层级都是） | 该地块/该国的地盘切成连通块，取**像素最多的那一块的几何中心** |
| **CK3** 伯爵领、男爵领 | 自己的**几何中心** |
| **CK3** 公爵领、王国、帝国 | **法理首都的几何中心**（首都是个伯爵领，就落在那个伯爵领的重心上） |

几何中心 = 该头衔所有地块的像素重心（按像素数加权）。算出来的点要是落到海里或者
隔壁地块上（环形领地经常这样），就拉回自家离它最近的那块地的重心 ——
否则名字会飘到别人家去。

**EU4 为什么要先切连通块**：一个国家常常有好几块互不相连的地盘。1618 年的西班牙
领土横跨欧洲和美洲，直接拿全部地盘求重心，名字会掉进大西洋 ——
实测全体重心在 `(1794, 1158)`，而按最大块算出来是 `(1601, 1233)`，落在伊比利亚半岛上，
差了 200 多像素。所以先按省份邻接（那张 `adjacency.bin`）做并查集切块，
挑像素最多的那一块。省份层只有一块地，这一步等于没做。

以前 CK3 的公爵领以上是沿着首都链**递归取标签位置**的，会一路跟到首都下面的某个
男爵领身上，结果是落在伯爵领的边角而不是中间；现在只跳一层，取首都自己的重心。

### 地名字号

字号 = **名字实际待着的那块地在屏幕上有多大** × 0.15，也就是 `√像素数 × 缩放 × 0.15`，
细层级再乘一个倍率。它对缩放是**线性**的：放大两倍，字就大两倍。
只有一个 10px 的下限（再小看不清了），**没有上限** —— 上限正是"放大了字不跟着长"
的失真来源。

最细的两层（CK3 的伯爵领 / 男爵领，EU4 的地区 / 省份）字号再放大两成：
`TIER_FONT_BOOST = [1, 1, 1, 1.2, 1.2]`。这些地块本身就小，按面积等比算出来的字偏小，
缩到那一层看着费劲。它是常数倍率，所以线性不受影响。

两点容易踩：

- **字号按 `blockArea` 算，不按 `area`**。名字写在伊比利亚，字号就得按伊比利亚算；
  按整个西班牙帝国的地盘算会撑得离谱。
- **字号要吸附到一条几何阶梯上**（每级差 6%）。`ctx.font` 一改，浏览器就要重新解析
  CSS 字体简写、重新选字体，是 Canvas2D 里第二贵的一步；字号要是连续的，几乎每个
  标签都不一样，于是每个标签都要改一次 font。吸附之后同一级共用一次，肉眼看不出来
  （误差 ≤3%）。

### 地名人数的上限（这个坑踩过）

标注层有个每帧最多画多少个的上限（`MAX_LABELS = 4000`）。它**必须只限制"画出来的"**，
不能在挑候选的时候就截。

以前是在挑候选那一步截的，等于"只考虑面积最大的 4000 个"。CK3 有 **11295 个男爵领**，
于是放到最大、视口里明明有三十几个，却可能一个都进不了候选 ——
表现就是**男爵领的名字放多大都看不见**，而且换地方时好时坏（随机挑位置实测 20%
一个名字都不出）。现在候选只留一个防病态数据的上限（`MAX_CANDIDATES`），
真正的限量在画的时候按视口裁剪之后算。

配套的一点：几万个候选逐帧循环没问题，但**不能逐个量宽** ——
`measureText` 是贵操作。所以先按位置粗筛（余量按字号算，够长地名用），
过了粗筛才量宽。

### 地名每帧的开销

平移时相机每帧都在动，标注层就每帧全重画一遍。实测 EU4 年份层一帧 665 个标签：

| 每帧调用 | 优化前 | 现在 |
|---|---|---|
| `ctx.font` 赋值 | 665 | **3**（= 字号桶数） |
| `measureText` | 665 | **0**（量宽缓存命中） |
| `strokeText` / `fillText` | 665 / 665 | **0 / 0**（全走贴图） |
| `drawImage` | 0 | 665 |
| 读 `clientWidth` | 665 | **1** |

三件事：

1. **字形贴图缓存**。`strokeText`/`fillText` 要现场栅格化汉字，带描边等于画两遍，
   这是拖影的真凶。同一段文字 + 同一个字号 + 同一个颜色只画一次到离屏 canvas，
   之后每帧 `drawImage`。平移时缩放不变，命中率几乎 100%。贴图按 `devicePixelRatio`
   渲染，高分屏上不糊；总像素超 16M 就从最老的开始丢。
2. **字号分桶**（见上）。
3. **`clientWidth` 不能在标签循环里读**。读它会逼浏览器同步重排，几百次就是灾难。
   现在一帧只读两三次，存在 `this.cssW/cssH` 里。

这些数字是测试里数出来的，不是估计 —— 见下面第 1c 组断言。

EU4 的层级和 CK3 正好一一对得上（五级），所以 `titlemap` 那张 5 行的表、
前端的五个视图按钮、着色管线全都原样复用。EU4 这边现在装的是
1444 / 1618 / 1800 / 地区 / 省份。

**但有两点必须说清楚：**

1. **名字默认是中文的。** EU4 官方只带英法德西四种本地化，没有中文；编辑器用的是
   **汉化 mod**里的名字（装了汉化的话）。`build_eu4.py` 会自动读项目里的
   `eu4_names_zh.json`，取不到就退回游戏自带的英文名。英文原名没丢 ——
   悬停卡片上鼠标停上去能看，**搜索也两种语言都认**（搜 `Stockholm` 和
   搜 `斯德哥尔摩` 是同一个结果）。想强制用英文：`python build_eu4.py --hanhua none`。
   编码细节见下面「汉化 mod 的双字节编码」。
   游戏里查不到名字的条目，用 key 收拾出来（`west_american_sea_superregion` →
   `West American Sea`），这是**显示兜底**，不是编数据。当前这套 5558 个真节点
   （含 1463 个国家节点）**全部**有中文名。
2. **颜色大半是编辑器生成的。** `definition.csv` 给了 3272 个陆地省份各自的原色
   （就是省份图上的颜色），`area.txt` 里有 50 个地区自带 `color`；国家用
   `common/countries` 的国旗色。只有**地区**这一层多数没有配色数据，是编辑器按
   "同一个父级（区域）下的兄弟"用黄金角散出来的，纯粹为了看清层级，不是游戏里的东西。
   数量记在 `meta.generatedColors` / `meta.officialAreaColors` 里。

### HOI4

| 用途 | 文件 |
|---|---|
| 地块边界（5632×2048 的 24 位 BMP） | `map/provinces.bmp` |
| 地块编号与原色、类型 | `map/definition.csv`（**8 列**，见下） |
| **开局剧本**（日期 + 名字） | `common/bookmarks/*.txt` |
| 省份 → 州 | `history/states/*.txt` 的 `provinces = { ... }` |
| 省份 → 战略区 | `map/strategicregions/*.txt` |
| **归属**（各剧本） | `history/states/*.txt` 的 `history = { owner = ... }` |
| 执政意识形态（挑国家名用） | `common/bookmarks/*.txt` 的 `ideology`，缺了退回 `history/countries` 的 `ruling_party` |
| **国家地图色** | `common/countries/colors.txt`（**正表**，能用 `HSV { ... }`），缺了才退回 `common/countries/<Name>.txt` |
| 名字（**官方简体中文**） | `localisation/simp_chinese/*.yml` |
| 洲名表（定义表第 8 列的序号） | `map/continent.txt` |

HOI4 这边的坑：

- **开局剧本不能写死。** 日期和名字都在 `common/bookmarks/*.txt` 里，DLC 会改那些文件
  （每个国家块都带 `version = base_game` / DLC 标记）。实测：

  | 剧本 | 日期 | 中文名 |
  |---|---|---|
  | `the_gathering_storm.txt` | `1936.1.1` | 风暴前夜（默认） |
  | `blitzkrieg.txt` | **`1939.8.14`** | 闪电战 |

  注意第二个**不是 1939.1.1** —— 早先按 1939.1.1 烤，差了这半年里
  **11 个州**的归属：意大利吞并阿尔巴尼亚（`STATE_44 ALB→ITA`）、
  梅梅尔（`STATE_188 LIT→GER`）、斯洛伐克独立与匈牙利吞并喀尔巴阡
  （`STATE_70/71 CZE→SLO`、`STATE_664/73 CZE→HUN`）…… 现在从剧本读，日期就是对的。
- **每个剧本里同一国家的执政党可能不一样**，而国家名有意识形态变体，
  所以得**按剧本各挑一份**：1936 的西班牙是"西班牙"，1939 的剧本把它标成
  `fascism`，于是显示"**西班牙国**"；1939 的日本同理（`JAP_fascism`）。
  剧本里写了就用剧本的，没写的退回 `history/countries` 的 `ruling_party`。
  实测跟 `history/countries` 不一致的：1936 有 5 个、1939 有 7 个。
- **国家颜色要读 `common/countries/colors.txt`，不是每个国家自己文件里那个。**
  每国文件（`common/countries/Germany.txt`）里的 `color` 常常是**占位值**，
  实测 1936 的 90 个国家里有 **30 个**跟正表不一样，而且好几个国家共用一个色 ——
  `(152,130,191)` 被多米尼加/萨尔瓦多/埃塞俄比亚/利比里亚/尼泊尔/新西兰/巴拿马/坦噶
  **8 个国家**共用；瑞士那个甚至是 `(33,14,19)` 的**近乎全黑**（正表里是鲜红
  `(224,5,5)`）。画出来就是"很多国家没有颜色"。

  > 正表里允许写 `HSV { 0.1 0.15 0.4 }`（德国就是），而解析器的 `as_rgb()`
  > 早先只认**小写** `hsv` —— 于是整张正表一个都读不进来，全体退回占位值。
  > 现在前缀不区分大小写了。

  剩下的"共色"（正表自己也给 8 个国家同一个色）是**游戏数据**，不编。
- **这就是"全开 DLC"的版本 —— 而且不用做任何事。** HOI4 和 CK3/EU4 不一样：
  它的 DLC **内容也一起装在游戏本体目录里**（`dlc/` 下那些子目录只有美术/界面/音效），
  剧本文件里用 `version = <DLC>` 标出每一块内容归哪个 DLC。实测 1936 剧本列的
  85 个国家：

  | version | 个数 |
  |---|---|
  | `base_game` | 37 |
  | `no_compromise_no_surrender` | 19 |
  | `gotterdammerung` / `trial_of_allegiance` | 各 5 |
  | `by_blood_alone` / `thunder_at_our_gates` / `graveyard_of_empires` | 各 4 |
  | `arms_against_tyranny` | 3 |
  | `la_resistance` / `man_the_guns` / `no_step_back` / `peace_for_our_time` | 各 1 |

  烤缓存时**不过滤 `version`**，所以读到的就是全开 DLC 的内容 ——
  芬兰、巴西、阿根廷、秘鲁、冰岛、捷克斯洛伐克、埃塞俄比亚、奥地利、匈牙利、瑞士
  这些 DLC 专属国家都在图上（测试里钉住了）。

  **但光记 `owner` 还不够。** 归属还会用这两种写法，DLC 全靠它们：

  ```
  history = {
      owner = CHI
      1936.1.1 = {
          IF = {
              limit = { has_dlc = "No Compromise, No Surrender" }
              transfer_state_to = SIC        # 开局把这块州移交给川系军阀
          }
      }
      1938.10.25 = {
          IF = { limit = { has_dlc = "..." } remove_core_of = SIC }
          owner = CHI                       # 又收回来
      }
  }
  ```

  * `transfer_state_to = TAG` —— **开局移交**；
  * `IF = { limit = { has_dlc = "..." } ... }` —— 开了那个 DLC 才生效。
    实测州历史里 **57 个 `limit` 全是 `has_dlc`**，没有别的条件，所以按
    "全开 DLC"算它们全部成立。

  早先只认 `owner`，这些州就全留在国民政府手里 —— **1936 看不到川系军阀**。
  现在：1936 有川系军阀 45 省、东北军 17、察南 27、鲁系军阀 40、粤系军阀 32、
  桂系军阀 40、青海马家军 65（中华民国只剩 227 省），到 1939 全被收回
  （中华民国 403 省）—— 1936 的国家数从 90 变成 **96**。

  > 剧本里列的那 9 个 `SIC`/`XIC`/`HBC`/`SND`/`GSM`/`NXM`/`KHM`/`GDC`/`COG`：
  > 前 6 个靠 `transfer_state_to` 在 1936 拿到州；`GSM`/`NXM`/`KHM` 在游戏数据里
  > 确实只有 `add_core_of`、没有移交，所以仍然不上图。

  > **没读的是你启用的 workshop mod**（`dlc_load.json` 里那 6 个）。
  > 想要"带 mod 的版本"就得再加一层覆盖，跟 EU4 那边的 `--mapdir` 一个道理 ——
  > 要的话说一声。
- `definition.csv` 是 **8 列**：`province;r;g;b;type;coastal;terrain;continent`。
  比 EU4 多出的 `type` 直接写 `land` / `lake` / `sea`，所以**不用再去翻
  `default.map` 的名单**（EU4 那边要翻）。13414 个省份里陆地 10155、海 3133、湖 126。
- **省份自己在游戏里没有名字。** 有名字的是国家、战略区、州，以及「胜利点」（城市），
  胜利点的键就是省份 id：`VICTORY_POINTS_3838: "阿雅克肖"`。
  10155 个陆地省份里只有 **1492 个（14.7%）** 有城市名，剩下的是货真价实的无名地块 ——
  **不编名字**，所以省份层的地名本来就稀疏，那是游戏数据不是漏抓。
  无名的省份在悬停卡片上仍然看得到它的编号（卡片标题就是 `#<id>`）。
- **国家名有意识形态变体**，这是必须处理的：`SOV` 是"俄罗斯"，但 1936 的苏联
  得显示 `SOV_communism` = "苏维埃联盟"；`GER_fascism` 是"德意志国"。
  所以先读 `history/countries/*.txt` 的 `ruling_party`，再按
  `TAG_<意识形态>` → `TAG_DEF` → `TAG` 的顺序挑。实测出来的名字：
  德意志国 / 苏维埃联盟 / 日本帝国 / 中华民国 / 联合王国 / 美利坚合众国 ——
  跟游戏里显示的一致。
- **附属国还要再套一层 cosmetic（换名字也换颜色）。** 光有意识形态不够：
  `MAN_fascism` 是"**大清**"（溥仪复辟那条线），而 1936 的东北该是"**满洲国**"。
  游戏里的键规则是

  ```
  <cosmetic>_<意识形态>_<自治级别>    MAN_JAP_fascism_autonomy_wtt_imperial_protectorate = 满洲国
  ```

  cosmetic tag 的命名约定是 `<附属国>_<宗主国>`（`MAL_UK` / `RAJ_UK` / `INS_HOL` / `CAN_UK`…），
  颜色在 `common/countries/cosmetic.txt`、名字在
  `countries_cosmetic_l_simp_chinese.yml`；附属关系（谁是谁的、什么自治级别）写在
  **宗主国**的 `history/countries/*.txt` 里：

  ```
  set_autonomy = { target = MAN autonomous_state = autonomy_wtt_imperial_protectorate }
  ```

  烤缓存时先摆一串候选键（`<cos>_<意识形态>_<自治>` → `<cos>_<意识形态>` → `<cos>`
  → `<tag>_<意识形态>` → `<tag>`），再挑第一个查得到的 —— 反过来会卡死
  （要先知道键才能取文本、又要先有文本才能挑键）。实测 20 个附属国：
  满洲国 / 英属印度 / 荷属东印度 / 比属刚果 / 英属缅甸 / 巴勒斯坦托管领 /
  叙利亚共和国 / 黎巴嫩共和国 / 外约旦酋长国 / 科威特谢赫国 / 蒙疆联合自治政府 ……
- **归属只在 `history` 块的 `owner` 和带日期的块里**。1081 个州里只有 **57 个**
  的日期块动了归属，换算成省份是 **195 个**：捷克斯洛伐克→德意志国（慕尼黑协定）、
  奥地利→德意志国（德奥合并）、青海马家军→中华民国……所以 1939 那一层是有东西看的
  （这 195 个是相对 1936 说的，跟剧本日期无关）。
- 战略区一共有 304 个，但其中 **61 个是纯海域**（海军战区）。海/湖在编辑器里是
  **锁住的伪头衔**（跟 CK3/EU4 一致），所以这 61 个不进树，实际用了 243 个。
- **没有"导出 mod"这条路。** HOI4 的 `provinces.bmp` 是**省份 id 表** ——
  那里的颜色是编号，不是显示用的地图，游戏的政治地图颜色来自
  `common/countries` 的国家色。改了 `provinces.bmp` 游戏画面不会变，
  所以这个模式下工具栏的「导出 mod」按钮是收起来的，不给你一个点了没反应的按钮。
  真要做 HOI4 的配色 mod，该改的是 `common/countries/*.txt` —— 想要就说。

| 用途 | 文件 |
|---|---|
| 地块（8192×3616 的 RGB 图，**像素本身就是省份 id**） | `game/map_data/provinces.png` |
| 省份 → 州 | `game/map_data/state_regions/*.txt` |
| 州 → 战略区 | `game/common/strategic_regions/*.txt`（**自带 `map_color`**） |
| **1836 归属** | `game/common/history/states/00_states.txt` |
| 国家地图色 | `game/common/country_definitions/*.txt` |
| 名字（**官方简体中文**） | `game/localization/simp_chinese/**/*.yml` |

V3 这边的坑：

- **省份 id 是 24 位**：`provinces.png` 是一张普通 RGB 图，像素的 `xRRGGBB`
  直接就是省份 id（`state_regions` 里写的就是这个，实测 99.2% 对得上），
  **没有 definition.csv** 这种东西。可渲染管线是 **R16UI（上限 65535）**，
  装不下 24 位 —— 所以烤缓存时把 id **重映射成密集序号 1..40875**。
- **归属表不能按二维存。** 一张 `省份数 × 层级数` 的纹理，宽度是 40876，
  超过显卡的 `MAX_TEXTURE_SIZE`（常见 16384）——真显卡上同样传不上去。
  现在归属表**拍平成一维**（索引 = 层级 × 省份数 + 省份），宽度压在 4096 以内。
  这条对四套游戏都生效（只是 V3 才逼出这个问题）。
- **归属要看最低单位（省份），不能按这个州归谁算。** 一个州块里可以有好几条
  create_state（州被几个国家瓜分时就是这样）：实测 **675 个州块里有 1148 条**
  create_state，**218 个州是分开的**。每条里的 owned_provinces 才是真正占着的地。
  按州取国家的话，被瓜分的州会整块算给一家 —— 那样只有 230 个国家，现在对的是 **443 个**
  （例：STATE_ABU_DHABI 分属 ABU、BHN、OMA，就是特鲁西尔阿曼那一片）。

- **V3 只有一个开局**（1836.1.1），没有剧本系统 —— 但年份配粒度那套照样成立
  （细层级 = 战略 / 地区 / 省份）。
- 战略区一共 142 个，但其中 **106 个是纯海域**（`water_strategic_regions.txt`），
  陆上只有 36 个。
- **省份名是"hub 名"。** 州块里的 `city` / `port` / `farm` / `mine` / `wood`
  都是 hub（城镇点），每个都有自己的名字，键长这样：

  ```
  HUB_NAME_STATE_UUSIMAA_city = 赫尔辛福什
  HUB_NAME_STATE_UUSIMAA_port = 奥布
  ```

  所以**不是每个省份都有名字** —— 实测 40717 个省份里 **2788 个**有（就是当 hub 的那些），
  其余无名，只看色块。州和战略区则都有中文名。
- **没有"导出 mod"这条路**：跟 HOI4 一个道理，`provinces.png` 的像素是 id 不是显示地图。

| 名字（官方简体中文） | `game/main_menu/localization/simp_chinese/**/*.yml` |
| **1337 归属** | 从开局存档解出来的 `eu5_1337_location_owners.csv`（**不在游戏目录里**） |

EU5 这边的坑：

- **本地化和色表在 `main_menu/` 下，不在 `in_game/` 下。** 我在这件事上栽过两次：
  找国名时把 `in_game/localization` 翻了个底朝天（空的），找 `map_XXX` 的定义时又
  只翻 `in_game/common`。正确的路径就是上面表里那两条。
- **地图是 16384×8192。** 默认 `build_eu5.py` 用 `--scale 2` 烤半尺寸（8192×4096，就是
  启动页那张「EU5 原版」）；`--scale 1` 出原尺寸，落到 `data_eu5_full/`，启动页多一张
  「EU5 原尺寸」。
- **原尺寸**必须**分块**，这不是优化是硬需求：整张解压成 `Uint16Array` 是 **268MB**
  堆，做成 R16UI 纹理又是 **268MB** 显存，而且 16384 正好顶到常见显卡的
  `MAX_TEXTURE_SIZE`。所以烤缓存时顺手切成 **4×4 张 4096×2048**（压缩后合计才 4MB），
  前端按视野取块（`web/js/tilemap.js`）、用 `sampler2DArray` 的 16 层装；
  取样统一走 `provAt()`（`uUseTiles == 0` 时退化成原来那张整图的写法，**半尺寸一条
  路径都没变**）。单文件版把那 16 块也内嵌进去（所以它从 20MB 长到 37MB）。
- **国家地图色是命名色，不是 `color2`。** `setup/countries` 里几乎每个国家都写着
  `color2 = rgb { 16 41 202 }` —— 那是**共用的次要色**，拿它上色会出现 669 个国家
  一个颜色。真正的地图色是 `color = map_XXX`，去 `main_menu/common/named_colors/02_map.txt`
  查表；也有一批是直接写 `rgb {}` / `hsv {}` 的，两种都得认。
- **`hsv` 是 0~1 的小数，别转 int。** `MZB = { color = hsv { 0 0 0.60 } }`（姆扎卜）
  用 `int()` 一截就成 `0 0 0`，国家直接变纯黑 —— 这个坑是我盯着"灰色国家"才挖出来的。
- **1337 归属只能从存档里来**（游戏文件里没有开局归属）。存档的形状：`SAV0` 明文头
  （32 字节，v1 是 24）+ **一个 zip**，里面是 `gamestate`（172MB）和 `string_lookup`
  （658KB）；`gamestate` 是**结构化二进制**（字节熵 5.26，没有二次压缩），开头是
  28573 条地块名表。**字段名是编译期的 game token —— 既不在存档里，也不在游戏目录里**，
  所以"找字段名"这条路直接死了；现在归属用那份 CSV（`location, owner_tag, owner_id`
  三列，28573 行）。`eu5/save.py` 里把已知的 lexeme id、三张表的 token 位置都写下来了，
  以后要读别的年份的 `ownership_history`，从那儿接着翻。
- **层级树有六层，界面只留四层。** 大洲 / 次大陆 / 区域那三层按需求去掉了 —— 树里的
  节点还在，但**不给行号**（`tree_row()` 返回超范围的号），前端按"序号超范围"判为锁住，
  看得见、涂不了。层级数是从 `TIER_ORDER` 算出来的，**别在别处写死行号**：我改层数时
  就是漏了一处写死的 `lv < len(TIER_ORDER)`，把省份和地块整层跳过了 —— 界面上那两层
  直接空白。
- **剧本层只叠最细的两层地名**（EU5 是省份 + 地块）。地区、战略那些不叠，不然一开门
  就是一堆大区名，把国名压住。
- **荒地（不可通行）是可以一块一块涂的。** 1878 块里 1875 块本来就在层级树里有自己的
  节点和中文名（约顿海姆、哈当厄尔高原、赤石山脉……），以前被一个共享的 `#impassable`
  伪头衔**六层全盖住**，于是"1818 块荒地共用一个颜色"，想给其中一块单独上色做不到。
  现在只盖**粗层**（1337/地区/省份照旧是那块灰），**最细那层留给地块自己的节点**。
  两个开关在「填色」那一组：
  - **荒漠 · 涂色**（默认关）：关着时荒地一律显示灰（跟以前一模一样）；开了才显示你给它
    上的色。实现上借了颜色表的 **alpha 通道**当"这是荒地"的标记（那个通道别处没用过），
    着色器取一次就够了，不用多传一张纹理。
  - **荒漠 · 自动涂色**（按钮）：按"跟周边国家接壤的**边界像素**占比"给荒地上色，
    **严格过半**才算 —— 一块荒漠旁边或许挨着三个国家，但 80% 的边属于同一家，那它就
    该是那一家的。这个归属是**烤缓存时算好的**（`wastelandAuto`），前端把它当成一种
    **地图原版颜色**写进颜色表 —— 所以关掉「填色·颜色」照样看得见、不进涂色导出、
    也不进撤销历史；玩家自己涂过的地方仍然以玩家为准（手绘层在头衔色之上）。
    认的规矩是"荒地的**整条陆地周长**里，贴着某一个实体的比例**严格过半**"：

    - 分母是**完整陆地周长** —— 无主地算 ✓、**别的荒地也算** ✓（两块荒地交界那条边
      以前两边都没算），水不算；
    - 分子里，玩家**涂过色**的邻居按**颜色**归类（你涂的一整片就是一个实体 ✓），
      没涂的按**当前层级**的主人来算；
    - 所以一块荒漠旁边的地盘被你涂成一色之后，那块荒漠就跟着变成你的颜色 ✓。

    权重来自构建期烘的 `wastelandPerimeter`（每块荒地 → [[邻居, 共享边像素数], …]），
    应用侧只做一次加权投票，比"逐像素反推"稳得多。归属还**按层级各存一份**
    （`wastelandAutoByTier`）：在地区层看就按"哪个地区占的边多"，切到省份层就按省份算。
    切到"这一层本来没主"的层级时，会自动**还原成原版色**（不会残留上一层的颜色）。

  **「自动涂色」是按一下算一次的动作，不是开关。** 它按你**当前看到的颜色**
  （原版色 + 你涂的色 + **上一次按出来的自动色**）给荒地算一遍，不做事后处理 ——
  所以**再按一下就是再传染一圈**：上一圈涂上的荒地，这一圈就成了"票"。
  想让荒漠的颜色顺着链子往外走，就多点几下；「清除」把自动色全部还原成原版灰
  （你自己涂的地块不受影响）。这样"迭代到固定点"这件事交给你手指，代码里不用搞循环。

  这些字段（`wastelandPerimeter` / `wastelandAutoByTier` / 每层指向自己 / 荒地名字 /
  `hideLabel` / `meta.numTitles`）都由 **`patch_wasteland.py`** 统一加工，**幂等**，
  可以反复跑；`build_data.py` / `build_eu4.py` / `build_eu5.py` / `build_hoi4.py` /
  `build_vic3.py` 收尾都会自动调它 —— 所以**重烤不会再把这些丢掉**。

  它按**数据自己的形状**认模式（EU4 有 `provinceColors`、EU5 有 `eraDates`、
  CK3 有 `deJureYear`）：认错了会把名字灌串（省份号两边会撞），所以顺序不能反 ——
  **先认 EU4/EU5，最后才轮到 CK3**。EU4 的荒地中文名直接读汉化 mod 的本地化
  （`eu4_names_zh.json` 那份是过滤过的，荒地全被滤掉，不能用）。

## 汉化 mod 的"双字节"编码


EU4 官方没有中文，汉化 mod 的做法是**顶替 english 槽位**，把汉字塞进
`localisation/*_l_english.yml`。那些文件不是普通 UTF-8 中文，直接打开是一堆控制字符
—— 这就是所谓"双字节"。`eu4/hanhua.py` 里写全了解码过程，摘要：

**外层**：整份文件是"原始字节流按 cp1252 解码"后再存成 UTF-8 的，所以第一步要倒回去：
`文件 → utf-8 解码 → 按 cp1252 编码`。注意是 **cp1252 不是 latin-1** ——
0x80–0x9F 那一段两者不一样，用 latin-1 反解会把 0x9A（š）、0x97（—）这些字节弄丢，
后面怎么修都对不齐（这个坑我踩了整整一轮）。

**内层**：汉字是三字节一组 `<标记> <低> <高>`，码位 = `(高 << 8 | 低) + 偏移(标记)`。
标记字节在 0x10–0x13，**低两位是标志位**：

| 标记 | 偏移 | 例 |
|---|---|---|
| 0x10 | 0 | `0x65AF` → 斯 |
| 0x11 | −0x0E | `0x4E1B` → 不 |
| 0x12 | +0x900 | `0x56B7` → 德 |
| 0x13 | +0x8F2 | `0x560E` → 开（罗） |

也就是 `(标记 & 2 ? 0x900 : 0) − (标记 & 1 ? 0x0E : 0)`（0x13 正好是 0x900−0x0E）。
ASCII 原样过。

这几个偏移是拿整份 `prov_names` 拟合出来的，判据是"解出来像不像真地名"：
斯德哥尔摩 / 君士坦丁堡 / 柏林 / 洛阳 / 石勒苏益格 / 科克斯霍尔姆 / 素可泰 /
孟加拉 / 纽伦堡 全部对上，3728 条零乱码。

```bash
python extract_eu4_zh.py --list                    # 列装了哪些汉化 mod
python extract_eu4_zh.py                           # 自动挑盖得最全的那个
python extract_eu4_zh.py --mod "C:\Steam\steamapps\workshop\content\236850\2976470733"
```

出 `eu4_names_zh.json`。这台机器上装了 **10 个** EU4 汉化 mod，自动挑会选省份名盖得
最多的那个；要指定某一个就加 `--mod`。

**名字是哪来的会记在文件里。** `eu4_names_zh.json` 顶上有一条 `_meta`，写着 mod 名、
workshop id、原始路径、各文件条数、抽取时间：

```json

  "path": "C:\\Steam\\steamapps\\workshop\\content\\236850\\2976470733",
  "workshop_id": "2976470733",
  "name": "Chinese Language Mod for 1.37",
  "entries": 4940,
  "extracted": "2026-10-02 02:28:33"

```

`build_eu4.py` 会把它提出来写进 `meta.hanhua`（只在数据里，界面不显示任何来源信息）。
装了好几个汉化的时候，这一条是用来分清"这份中文名到底出自哪个 mod"的。

覆盖情况：`definition.csv` 里 4941 个省份，汉化给了 **3925** 个中文名 ——
正好是地图上真有像素的那些省份。剩下 1016 个本来就不在地图上（随机新世界预留），
游戏本体也没给它们名字。

**地图上用得到的 key 是"从游戏数据推"的，不是按名字形状猜的。**
`area.txt` / `region.txt` / `superregion.txt` / `continent.txt` 里的分组名，加上
`definition.csv` 的每个 `PROV<id>`、`common/country_tags` 的每个国家 tag

## 渲染是怎么做的

画面就是干净的色块：头衔自己的颜色、深色边界。**没有铺任何地形贴图** ——
游戏目录里那几张地形图（`colormap.dds`、`flatmap.dds`）是喂给它自己渲染管线用的，
单独揪出来当底纹又灰又花，压在地块上显脏。想要淡一点的话，调低工具栏的「浓度」。

**海、湖、河、山、荒地也都有自己的颜色，但它们是锁死的。** 这些地块在游戏里是 province，
只是没有归属（CK3 的分类在 `map_data/default.map`；EU4 是 `default.map` 的
`sea_starts` / `lakes`，加上 87 个"不属于任何地区"的陆地省份 = 不可通行荒地，
名字是 Namibia / Rub' al Khali / Himalaya / Takla Makan / Alps / Pyrenees 这些）。
编辑器把它们各做成一个以 `#` 开头的「伪头衔」，好跟真头衔走同一套着色逻辑、
五个层级都填满不留洞。

但它们**不能取色、不能涂色、悬停也不高亮**，鼠标移上去是禁止符 —— 因为游戏里
根本没有对应的字段可写，让你改一个存不下来的颜色是骗人。想要别的颜色，改
`build_data.py` 或 `build_eu4.py` 顶上的 `SPECIAL_CATEGORIES` 再重跑一次。

> EU4 其实给海洋也编了 area/region/superregion（`baltic_sea_region` 之类），
> 编辑器没用它们 —— "海不能涂"这条在三个模式里保持一致，代价是丢掉了
> 95 个海洋行政区（记在 `meta.droppedSeaTitles`）。想开的话改 `build_eu4.py`
> 里 `land` 的定义就行。

**空缺就显示成空缺。** 某个层级确实没有对应归属的地块，画面上是一块中性灰，
悬停会诚实地写「（无）」。不做任何"就近继承"—— 那会凭空造出不存在的地缘关系。
CK3 目前实测帝国/王国/公爵领/伯爵领四层都是 100% 有归属，男爵领层只剩 2 个省份是真空缺；
EU4 五层都是 100%（海/湖/荒地归伪头衔兜住了）。

着色全程在 GPU 上，三层间接查表：

```
屏幕像素 → 省份 id 纹理 → (省份, 层级) 归属表 → 层级节点序号 → 颜色 LUT → 实际颜色
```

这么绕是为了**改色够快**：LUT 是一张 256×N 的小图，改一个地方的颜色只往里写
一个像素，那张大纹理完全不用动。涂色是即时的。整张 LUT 才 71 KB，
所以「填色」开关一切就直接整张重传（`flushLut()`），不逐个写。

**LUT 里放的是"这一刻该显示的头衔色"，不是"头衔被改成了什么色"。** 这两者在有涂色时
不一样，而且差一点就出 bug：玩家填色**同时**改了头衔色和手绘层，于是关掉
「填色·颜色」之后，底下那份改过的头衔色还顶在 LUT 里 —— 填色永远藏不掉。
现在 `lutColorOf()` 说了算：开着填色才把涂色写进 LUT，关掉就换回游戏原色。
于是两个开关真正正交了：

| | 头衔·颜色 开 | 头衔·颜色 关 |
|---|---|---|
| **填色·颜色 开** | 游戏原色 + 你涂的地方是你的色 | 只有你涂过的地方有色 |
| **填色·颜色 关** | 游戏原色（你填的色全藏起来） | 空白 |

导出不受影响 —— `state.titles.colors` 里始终留着改过的颜色，关掉填色只是不**显示**它。

**「填色·边界」分的是"同色 + 同标记"的块，不是只看颜色。** 两张纹理各管一件事：

| 纹理 | 格式 | 存什么 |
|---|---|---|
| `uPaint` | RGBA8 | RGB = 涂的颜色，alpha = 涂没涂 |
| `uPaintLabel` | R16UI | 标记编号 + 1（0 = 没涂） |

颜色那张表塞不下标记（四个通道刚好用完），所以标记单开一张。
着色器里的 `paintDiffers()` 先比"涂没涂"、再比颜色、最后比标记编号 ——
这跟 JS 那边切手绘色块的规则（`rebuildPaintBlocks`）**必须是同一套**：
同色但不同标记的两块中间得有根线，不然明明是两个标记，看着还是一坨。

地块之间的分界线是按**归属**判的，所以同一个伯爵领内部的男爵领之间不会画线。
线本身不是"这个像素跟邻居不一样就涂黑"——那样分界线两侧的像素各自都满足条件，
线会变成两个地图像素宽、两边各占一格的半透明带子（放大 8 倍就是 16 个屏幕像素的
灰雾，缩到全图又整个漏掉）。现在的做法是沿四个方向找到最近那条缝、取垂距，
再套一条宽度锁在**设备像素**上的抗锯齿斜坡：屏幕上永远是同一条细实线，缩放不变。

粗细和深浅是两个旋钮，在 `web/js/gl.js` 的 `MapRenderer` 构造函数里：

```js
this.borderWidth = 1.6;      // 线宽，设备像素
this.borderStrength = 0.8;   // 往底色里混多少
```

**两个色块之间的接缝也是同一个道理。** 反锯齿要在一个屏幕像素里摊 4 个采样点，
关键在于那 4 个点的偏移是按**屏幕**折算的（`uMapPerPx`），不能写成固定的地图像素。
写成固定的 0.25 个地图像素，放大 18 倍时那就是 4.5 个屏幕像素，四个点摊开跨 9 个
像素——两个色块中间会被平均出一条 **9 像素宽的纯色混色带**（正好是两色的 50/50），
越放大越糊。锁进一个屏幕像素之内，接缝就永远只剩一格过渡。

采样点用的是 4 点旋转网格（RGSS）而不是正方形四角：斜边上的过渡层次更多，
不会出现"要么纯色、要么 50%"的硬台阶。

## 测试

`test_modes.js` 开头先查着色器，再验行为。

着色器那段是静态检查 + 公式验算：着色器是字符串，JS 语法检查碰不到它，而它最阴的
出错方式是 uniform 声明了却忘了写进 constructor 那张名单 —— 那样 `getUniformLocation`
拿到 `null`，后面 `uniform1f(null, ...)` 是**静默 no-op**，参数永远是 0，界面上一句
报错都没有。这里把"声明的都在名单里""名单里的都存在""每个都被 `render()` 传了值"
全对一遍，另外按源码逐字重算两段公式：边界线在屏幕上到底几像素宽、
两个色块之间的混色带在屏幕上到底几像素宽（后者是拿用户截图里量到的 8 像素平台
反推出来的，测试里留了一条复现）。

行为那段不重写逻辑，而是把 `web/js` 下那几份源文件按 `build_standalone.py`
的办法拍平，喂一套假 DOM / 假 localStorage / 假 WebGL，让**真正的** `boot()` 拿
**真实缓存数据**跑起来，再照着该有的行为一条条验（术语切换、悬停链条、取色涂色还原、
三个游戏的存档互不干扰、海湖荒地锁得住、EU4 导出的 zip 里 BMP 和 CSV 内容对不对）。

## 干活规矩（2026-10-04 加的，血泪换的）

这一晚的翻车几乎都不是"难"，而是同一类失误反复犯。定死四条流程，不靠记性：

1. **动任何东西之前，先查谁在读它。** 移动 / 删除 / 改名之前全仓搜一遍引用，
   改完**立刻**跑全套自测（`node test_modes.js CK3`，六个模式都要跑）。
   吃过：搬 `parsers/`、挪 `data*/`（自测要扫它们，搬完没跑测试，第二天六片红）、
   合并 `preview*/`（四套截图丢了，只能重新生成）。
2. **删界面元素，就在同一个补丁里删掉所有引用。** 元素没了、代码还在 `$('id')` 上
   绑事件，就是启动即崩。同一个 `null.addEventListener` 崩了三次才补上守卫断言。
3. **一个改动失败两次 → 回退到能跑的版本，重新想，别在坏版本上叠第三刀。**
   `patch_capitals.py` 里连叠五轮才醒。动脚本之前先在 `_local/` 留一份能跑的。
4. **规格有歧义，先问一句话再写码。** 这一晚三次误读（"别给涂色专门画边界" → 我把开关
   删了；例外规则读反；地图坐标看反）都是一句话能问清的。一次性的活就做一次性的改，
   别顺手造通用机制、别顺手全量重跑。
