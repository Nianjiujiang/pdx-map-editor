## 二、WebGL 上下文丢失被误报成"着色器编译失败" ★

### 2.1 症状

用户发的管理员截图：

> 打开莫名其妙出来一个着色器连接失败。

管理员判断：**不是着色器写错了，是 WebGL 上下文超时 / 丢失**。
用户确认："我想要优化一个非常关键的问题……这是管理员的推断"。

### 2.2 根因

`boot()` 里原来的写法是：

```js
try {
  renderer = new MapRenderer(canvas, meta);
} catch (e) {
  rawErr('✗ 着色器编译失败：' + e.message);
}
```

**任何** `new MapRenderer()` 抛出的异常，都会被扣上"着色器编译失败"的帽子 ✗。
而 WebGL 上下文一丢，`compileShader()` / `getShaderParameter()` 会静默失败，
抛出来的恰好也是类似"编译失败"的错 —— 于是真凶被盖住了。

### 2.3 修法

1. **新增 `RendererSetupError`**，带 `stage` 和事实字段：
   `contextLost` / `glError` / `version` / `renderer` / `unmaskedRenderer` /
   `creationError` / `log` / `stageAt` / `maxTex`。
2. **建上下文**（`_createGL`）多试几组属性：
   `powerPreference: high-performance → default → unspecified`；
   同时接住 `webglcontextcreationerror` 的 `statusMessage`。
3. **编译前后都查上下文**：
   - `isContextLost()` 为真 → `context-lost`；
   - `getShaderParameter()` 返回 0 且上下文已丢 → **不怪着色器**；
   - `glError` `0x9242` → 上下文丢失，`0x0505` → 显存不足。
4. **监听器提前挂**：`webglcontextlost` / `webglcontextrestored` 在 `_build()` 之前就挂上，
   恢复时走 `_build()` 重建，不重新 `new MapRenderer`。
5. **分类上屏**：`describeRendererFailure()` 把 stage 翻译成人话；
   启动失败走 `handleBootRendererFailure()`，不再硬编码"着色器编译失败"。
6. **自动重试**（`createRendererWithRetry`）：
   - `context-lost` / `out-of-memory`：最多重试 2 次（共 3 次尝试）；
   - `no-webgl2`：只重试 1 次；
   - `shader-compile` / `shader-link` / `texture-limit`：**不重试**（重试也没用，还会掩盖日志）。

### 2.4 现在的错误分类

| code | 人话 | 重试 |
|---|---|---|
| `no-webgl2` | 这个浏览器没能创建 WebGL2（不是地图数据的问题） | 1 次 |
| `context-lost` | 显卡上下文在启动时丢失了（不是着色器写错了） | 2 次 |
| `out-of-memory` | 显存不够（贴图太大 / 驱动限制） | 2 次 |
| `shader-compile` | 真的着色器编译失败，带驱动日志 | 不重试 |
| `shader-link` | 真的着色器链接失败 | 不重试 |
| `texture-limit` | 贴图超过设备上限 | 不重试 |
| `renderer` | 其他初始化错误 | 不重试 |

新增 [`tools/check_renderer_error.js`](../tools/check_renderer_error.js)，**20 条断言**：
15 条分类 + 5 条端到端（包括"没有 WebGL2 时启动不白屏"）。
细节和排错过程在 [`修复-WebGL上下文丢失误报-2026-10-17.md`](修复-WebGL上下文丢失误报-2026-10-17.md) ✓

## 三、启动页导出 + 正式诊断报告

### 3.1 为什么按钮必须由 `log.js` 绑

用户：

> 能不能在加载界面就允许导出报错日志什么的，然后报错日志的格式也改的更官方更专业一点。

关键点：**编辑器自己没起来的时候，`app.js` 里的入口根本挂不上** ✗。
所以启动页那颗「导出诊断报告」由 `js/log.js` 自己绑：

- 按钮在 `web/index.html` 的启动页署名区，`id="btn-boot-log"`；
- `log.js` 只**绑已存在的按钮**，不创建 DOM、不改布局；
- 监听 `DOMContentLoaded` 再补绑一次，幂等（`btn.__pdxLogBound`）；
- 编辑器正常起来后，顶栏「文件 ▾ → 导出日志」和崩溃红条里的按钮导的是同一份。

### 3.2 报告格式 `pdx-map-editor.diagnostic/2`

原来四段：`[这是哪一份] → [当时的状态] → [错误] → [轨迹]`。
现在是六节正式报告：

```
报告头（编号 / 时间 / 格式 / 会话时长 / 结论）
[1] 环境信息     版本戳 · 运行方式 · URL / 协议 · 浏览器 / 平台 · 语言时区 · 屏幕 · UA
[2] 运行状态     地图 · 数据 · 视图 · 粒度 · 工具 · 改动数 · WebGL · 渲染器状态 / 详情
[3] 错误摘要     错误 / 警告 / 未捕获 / Promise 拒绝 / 累计次数 / 丢弃数 / 首末时间
[4] 错误明细     E-001 起，带 [ERROR] / [WARN] / [UNCAUGHT] / [REJECTION] / 位置 / 栈 / 次数
[5] 事件时间线   T-001 起，带相对毫秒
[6] 附录 JSON    schema / reportId / environment / runtime / errors / events / dropped
```

- 同一处错（忽略数字差异）合并计次，不会"一秒钟 60 条"把上限占满；
- 上限：错误 200 条、事件 400 条、单条消息 1200 字；
- UTF-8 + BOM、CRLF，记事本直接开；
- 文件名 `CK3_诊断报告_20261017_134501.txt`（没选图时 `pdx-map-editor_诊断报告_…`）；
- 报告里不再出现 `✓/✗` 这类手写标记；错误消息和堆栈保持原样（现场证据）；
- 不包含涂色图片、地图数据、游戏文件、`localStorage` 内容。

格式说明和 JSON 字段在 [`诊断报告格式-2026-10-17.md`](诊断报告格式-2026-10-17.md) ✓

### 3.3 构建戳：不是 `document.lastModified`

用户后来发现：

> 导出诊断报告的右边的那个日期疑似不是版本戳，而是当前时间……

确实如此。`document.lastModified` 在单文件 / 某些浏览器里就是**打开时间** ✗。

现在：

- `build_standalone.py` 打包时把时间写进 `<meta name="pdx-build" content="2026-10-17 13:56">`；
- 启动页显示 `构建 2026-10-17 14:25`，开发版显示 `开发版`；
- 诊断报告里的「版本戳」读同一个 meta；
- `tools/check_log.js` 加断言，防止有人改回 `lastModified`。
