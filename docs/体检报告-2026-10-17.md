> 体检对象：`web/` 下 11 个前端模块（约 1.1 万行 JS）+ `index.html` + 构建 / 自检工具。
> 方法：静态扫描（死代码 / 重复块 / 超长函数 / 越界与空引用）+ 动态基线（7 个模式的 `test_modes.js`、7 把 `check_*` 尺子、`bench_core.js` 四张图）+ 改动前后**同机同数据**对照。

## 0. 一句话结论

四个方向都拿到了可验证的收益：**认族全图扫快约 10 倍**、**涂色后重分组快约一成（细分层 -14%，全图模式 -6%）**、**启动时一处 O(组数 × 地块数) 的白扫改成 O(地块数)**；同时修掉四个真问题（`boot-inner` 找不到导致选图面板不拓宽、荒地名称被「地块 · 名称」连带、越界数据直接 TypeError、**WebGL 上下文丢失被误报成"着色器编译失败"** —— 见文末与 `修复-WebGL上下文丢失误报-2026-10-17.md`），并把 15 处设置取值和 12 处"推渲染器"的手写复制收成了两个公共口子。七个模式的自检通过数各 **+14～15**（有荒地的 +15，没荒地的 +14），失败数各 **-2**；两个产物已重烤，`check_standalone` / `check_mobile` 全绿。

## 2. 改了什么

### 2.1 代码复用

| 收口 | 之前 | 现在 |
|---|---|---|
| **设置数值读取** | 每处手写 `(state.set && state.set.xxx != null) ? Number(...) : 默认`，共 15 处，`pa/ra/ca` 还要再包一层除法 | `setNum(key, def)` 一个口子；非法值（NaN / 字符串）统一回退 |
| **推渲染器** | `if (renderer.x !== v) { renderer.x = v; renderer.dirty = true; }` 共 12 处，漏写 `dirty` 就是"滑条拖了没反应" | `pushRenderer(key, value, eps?)`；浮点按容差比，布尔严格比 |
| **地块身份** | `playerGroupTidsAt` / `playerGroupPidsAt` / `playerGroupTids` 三份几乎相同的全图扫，各拼各的字符串 | `identFieldsAt` 内核（复用一张临时表，零分配）+ `identWantAt` 快照 + `samePaintIdent` 比较；三个调用方共用一套判据 |
| **地名三开关** | 「地块 / 水域 / 荒地」的名称闸写了两遍半：先三分支判一次，后面又各判一次；荒地还被多判了一道 `showLabelsTitle` | 一条三分支判据，一处收口；荒地真正独立于「地块 · 名称」 |
| **帧内兜底** | `syncLayerSwitches` / `syncParentBorder` 裸调，一抛就把整帧的 `render()` 拖没 | `frameStep(name, fn)` 各自兜底，同一步只记第一条错 |
| **死代码** | 静态扫描出 7 处零引用：`isSpecialKey` / `PSEUDO_KIND_PREFIX` + `titleIndexOfPseudoKind` / `liveNameOf` / `findTitleByTag` / `titleIndexByKey` / `LabelLayer.pointsFor` | 全删；顺手删掉 `frameBody` 里没人接的 `paintedPoints()` 和 `syncLayerSwitches` 里没人读的 `_anyBorderOn` / `nm` |

改动量：`web/js/app.js` **+271 / -368**（净少 97 行），`labels.js` -13 行，`index.html` 1 行，`test_modes.js` +23/-3，`README.md` +40/-26，`docs/构建与开发说明.md` +6/-6。净减行数不是因为删功能，是因为三份重复循环和两套闸合成了各一份。
### 2.2 效率

| 项目 | 改前 | 改后 | 变化 |
|---|---:|---:|---|
| `playerGroupPidsAt`（VIC3） | 8.3 ms | **0.73 ms** | **约 11 倍** |
| `playerGroupTidsAt`（VIC3） | 6.9 ms | **0.75 ms** | **约 9 倍** |
| `rebuildPaintBlocks(all=true)`（VIC3） | 13.0 ms | **12.2 ms** | **约 -6%**（重复测量 12.0～12.4） |
| `rebuildPaintBlocks(all=false)`（VIC3） | 7.1 ms | **6.1 ms** | **-14%** |
| 每帧无用 `paintedPoints()` | 每个标签脏帧调一次 | 删除 | — |
| `buildSeaLabelPoints` 横跨判定 | 每个连通域都把全图扫一遍（EU5 数千组 × 4 万格） | 先 O(n) 收 min/max x，再每组 O(1) | 结果逐项一致（EU5 3217 点 / 23 个跨接缝点），启动不再有那趟白扫 |
| `titleAt` 边界判断 | 无 | 4 道廉价判断（越界回 `NO_TITLE`） | 热路径代价可忽略，换来不崩 |

具体做法：

- 认族那一趟原来每格都拼一个 `"名字|r,g,b"` 字符串；现在 `identFieldsAt` 把 `[name,r,g,b]` 写进一张复用数组，比较用四个 `===`。V3 4 万格从"4 万个短命字符串"变成"0 分配"。
- `rebuildPaintBlocks` 的 `all=true` 分支里，`_noOwn` / `hideLabel` / 伪头衔判定原来**逐省**跑（`isWasteOrWaterTid` 每次都要做键名前缀 + 名单查），现在按 **tid** 缓存成 `{noOwn, allowed, key}` —— 同一个国家的几万省只算一次。
- 并查集那趟每个邻居都 `find(pid)`，现在一进循环取一次、并完更新，4 万格约省 12 万次查找。
- `isPainted` 原来在收集完 `painted` 后又全图扫了一遍，现在在收集那一遍里顺手标掉。

### 2.3 鲁棒性

| 问题 | 修法 |
|---|---|
| **选图面板不拓宽**：`app.js` 找 `$('boot-inner')`，`index.html` 只有 `class="boot-inner"` 没有 id → 真实浏览器永远找不到，"两列卡片"时面板还是窄的（测试的假 DOM 会现造元素，所以以前静默通过） | `index.html` 补 `id="boot-inner"`；这条自检也从红转绿 |
| **荒地名称被「地块 · 名称」连带**：`drawLabels` 里后置的 `if (!_isWaterPt && !showLabelsTitle) continue` 会把荒地一起挡掉，跟 `index.html` / 交接文档写的"各管各的"相反 | 三分支闸只留一处；荒地只听「荒地 · 名称」。实测 EU5 只开荒地名称 → 1818 个点全是荒地，其余 0；EU4 → 87 个 |
| **越界数据直接崩**：`titleAt` / `isSpecialTid` 直接下标访问；`provinceAt` 读 `state.meta` 不判空；`hexToRgb` 对非字符串 `trim()` | 全部加空值 / 越界保护；`titleAt` 越界统一回 `NO_TITLE`，不会读到隔壁层的值 |
| **外部文件不可信**：`applyProject` 吃 `null` / 字符串 / 数字会 TypeError（导入 / 暂存 / 回滚三条路都走它） | 非对象直接回 0，**静默当"没有可识别内容"**；加了断言 |
| **导出画布拿不到 2D context**：设备内存不够时 `getContext('2d')` 返回 null，后面 `drawImage` 变成 TypeError | 两条导出路径都先判空，给一句人话 |
| **帧内一步坏了整帧不画**：`syncLayerSwitches` 一抛，后面的 `render()` 永远轮不到，画面冻住而错误只上屏一次 | `frameStep` 各自兜底；某一步坏了只跳过那一步，下一帧照常画 |
| **剧本层把势力名当地名叠画**（只在"开水域 / 荒地名称"时才会走到的隐藏路径） | 剧本层只放行水 / 荒地那两类自己的名称；陆地名归势力名那条路 |
| **横跨判定变量名写错**（历史坑：`_crossOf` 里把 `pp` 写成 `pos`，被 try/catch 吞掉 → 荒地名整批消失） | 这次顺手把那段重写成"一次扫描"，也把"别在没跑过的代码里靠印象写变量名"留在注释里 |
| **打开就报"着色器编译失败"**（管理员查了半天着色器，真凶是 WebGL 上下文丢失） | `RendererSetupError` 带 `stage`；`compile()` 先判 `isContextLost()` / `getError()`；拿上下文多试几组属性并接住 `webglcontextcreationerror`；监听器提前挂；`context-lost` / `out-of-memory` 自动重试两次；错误屏改成分类人话 + 刷新重试。详见 [`修复-WebGL上下文丢失误报-2026-10-17.md`](修复-WebGL上下文丢失误报-2026-10-17.md) |
| **加载界面导不出日志**（编辑器没起来时顶栏按钮还没挂上） | 启动页加「导出诊断报告」按钮，由 `log.js` 自己绑定（不依赖 app.js）；日志格式改成六节正式报告 + JSON 附录，见 [`诊断报告格式-2026-10-17.md`](诊断报告格式-2026-10-17.md) |

## 4. 发现了、这次**没动**的

这些不是"没看见"，是**这一轮不适合动**，列出来给下一场：

1. **七个模式仍有 11～26 条历史红账**，都不是这次引入的。典型三类：
   - **架构演进后过期的断言**：`#sea` 共享伪头衔、"地方边界宽度是倍率"、`W_TOP` / 水岸线旧通道 —— 对应的代码早退役了，测试还在按老形状量；
   - **数据后处理相关的老账**：空白剧本背景地形逐格一致、每一层指向自己那块（`65535` vs 真 tid）—— 属于 `patch_blank_era` / `patch_waste_pseudo` 那一侧，动它得重烤数据；
   - **测试夹具本身**：EU4HD 是测试在运行时临时塞进 `MAP_CHOICES` 的本地卡（产品表里没有它）；`check_import` 那 7 条（meta / titles / titlemap 逐字节对比、卡片管理面板、两块 tiles）在基线里就已经红了。
2. **超长函数**：`bindEvents` 662 行、`boot` 393 行、`rebuildPaintBlocks` 299 行、`buildSeaLabelPoints` 255 行、`pickMap` 246 行。拆分能提升可读性，但 `bindEvents` / `boot` 里大量是"接线"，拆出去收益不如风险；`rebuildPaintBlocks` 这轮已经做了局部减法，再拆得先定下数据后处理那几条口径。
3. **`gl.js` 的两处近似重复块**：射线设置的注释 / `waterIs(ip) && waterIs(q)` 让位那两句。它们是**着色器源码**，桩测不出来，改它必须真机验证（§构建说明里"改完着色器，桩是测不出来的"那条）；收益只是少几十行，不值得冒黑屏风险。
4. **`buildPseudoLabelPositions` 每层各建一次并查集**（最多 7 层 × 4 万格）。可以像 `buildSeaLabelPoints` 一样摊平，但它只在开图时跑一次、当前占总启动 20～30 ms，优先级低于真机性能问题。
5. **`_local/check_wiring.py` 与当前源码不同步**（它写着"荒地自动上色整套撤了"，而当前 `index.html` / `app.js` 里还在）。这是 `_local/` 里的临时尺子，不属于产品源码；下一场要用它之前先对齐，否则会假红。
6. **`docs/导入式地图-策划.md` 里的"六个模式 / 七个目录"** 是当时的策划存档，不是操作手册；没改，避免把历史决策文档改成"现在时"。

## 6. 给下一场的三句

1. **认族 / 地图身份只有一套内核了**：`identFieldsAt`（零分配）+ `paintIdentAt`（字符串）+ `samePaintIdent`（比较）。以后要加"按族"的功能，走这三个，别再写第四个全图扫。
2. **设置数值只走 `setNum`**，**推渲染器只走 `pushRenderer`**。新增滑条时这两步能省掉一半"拖了没反应"的 bug。
3. **帧里的新步骤用 `frameStep` 包**。一步坏掉不该让整张地图停画；同一步只记第一条错，控制台不会被刷爆。
