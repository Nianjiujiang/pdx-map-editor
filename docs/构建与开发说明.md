# 构建与开发说明

> 这份是给**想自己生成数据 / 改代码**的人看的。只想玩的话看根目录的 `README.md` 就够了。

## 需要什么

- **对应游戏的安装**：Steam 版会自动定位；找不到（或装在别处）就用参数手动指。
  解析器读的是安装目录里的地图和本地化文件。
- **Python 3.10+** 和 `numpy`。
- EU4 想显示中文国名，还需要汉化 mod（脚本会在 workshop 目录里自动找）。
- 改前端不需要任何构建工具：原生 JS，改完刷新即可。

## 生成数据

单文件版已经把数据烘进去了；只有换地图、换游戏版本、改解析时才需要这一步。

```bash
python build_data.py                       # CK3       → data/
python build_data.py --map <另一套图的 provinces.png> --out data_xxx --label "自定标签"
python build_eu4.py                        # EU4       → data_eu4/
python build_eu4.py --mapdir <另一套图的 map 目录> --out data_xxx --label "自定标签"
python build_hoi4.py                       # HOI4      → data_hoi4/
python build_hoi4.py --provinces <改过边界的 provinces.bmp> --out data_hoi4_alt --label "HOI4 修改边界"
python build_vic3.py                       # Victoria3 → data_vic3/
python build_eu5.py                        # EU5       → data_eu5/
python patch_wasteland.py                  # 荒地后处理（各构建脚本末尾会自动调用）
python patch_blank_era.py                  # 补一层「空白剧本」（同上，末尾自动调用；幂等）
python patch_waste_pseudo.py               # 把荒地挪成伪头衔（EU5 需要；同上，末尾自动调用；幂等）
python build_standalone.py                 # 出**轻量版**单文件（约 0.8 MB，不内嵌地图）
python build_standalone.py --all-maps      # 出全量版（35 MB，地图全烘在里面）
python build_packs.py                      # 把公开的 7 张地图打成 packs/*.pdxmap（约 27 MB）
python pack_map.py data --id 我的图 --label "我的图" --out 我的图.pdxmap
                                           # 打一个地图包（见「地图包」一节）
```

常用参数（`--help` 看全部）：

| 参数 | 说明 |
|---|---|
| `--ck3 / --eu4 / --hoi4 / --vic3 / --eu5 <目录>` | 手动指定安装根目录 |
| `--out <目录>` | 缓存写到哪（默认 `data_*`） |
| `--label <名字>` | 这套地图在顶栏「地图」里的显示名 |
| `--map <图片>` / `--mapdir <目录>` | 换一套地图文件（另一套 provinces.png / map 目录） |
| `--lang <语言目录>` | CK3 本地化语言，默认 `simp_chinese` |
| `--bookmark <日期>` | CK3 剧本地图那一层的日期，默认 `1066.9.15` |
| `--no-bookmark` | CK3 不生成剧本地图那一层（只剩法理那五层） |
| `--no-history` / `--no-dejure-history` | 不读历史文件，快很多，但年份层会变粗 |

## CK3 的 1066 剧本地图（2026-10-11 加）

层级栈**最上面**多一层「1066」——比帝国还粗。它画的不是法理，而是
**1066 年 9 月 15 日那一刻谁占着哪块地**：每块地归到管它的那个**非封臣**（独立君主），
**封臣的地盘算进宗主那一块**（CK3 的领地地图那个口径）。

**CK3 现在跟别的模式一个结构了**（用户点名的："取消 CK3 的特立独行，和其他模式一样"）：
`1066` 与 `空白剧本` 是**剧本层**（`meta.eraDates` 两条 ✓）、
帝国/王国/公爵领/伯爵领/男爵领**全是地区级** ✓
界面上的开关也跟着换成「势力 / 地区」两组（原来是 CK3 独有的「头衔」那一组 ✗）——
不过那会儿**只是把它藏起来了**（`titles-group` 按"有没有年代层"隐藏），没删：
CK3 有了剧本层之后这个判据在**每一个模式**里都成立，那组开关就永远藏着 = 纯死 UI ✗
2026-10-12 廿九点名，整组连监听器一起删了 ✓（它控的三样由「势力/地区」每帧算 ✓）
—— 这些全是**现成代码**跑出来的：前端整套年代层玩法只认 `eraDates.length` ✓
（粒度玩法 · "细层视图下这块地属于哪个国家" · 剧本层才画的那一圈边界 · 取色匹配表 ✓）

几条要记牢的：

- **数据在 `history/titles/*.txt` 里** ✓ 不是角色文件：
  `1066.9.15 = { holder = 1234 }` 是"谁持有这个头衔"，`liege = k_mesopotamia`
  是"这个头衔的持有者是 k_mesopotamia 持有者的封臣" ✓
  所以"谁不是封臣"= 顺着 liege 一路往上，走到没有 liege 的那一级 ✓
  （解析在 `parsers/ck3/parser.py` 的 `parse_title_history` / `top_liege` ✓
    ⚠ 同一个头衔有很多条日期段，要**按日期比大小**取最新的那条，别按文件顺序覆盖 ✓）
- **holder 有两种写法** ✗ 数字（`holder = 145292`）和**字符串 id**
  （`holder = japanese_fujiwara_9` / `ce3_pope_bonifatius_vii` ✓ 一万四千多条：
  日本 / 中国 / 教宗那些行政头衔都用它 ✓）。**两种都要收** ✓ ——
  只认数字的话，整个东亚会判成"1066 年无人占有"（一片灰 ✗ 踩过 ✓）
- 🔴 **`h_`（霸权 / hegemony）也要认** ✗ —— 2026 那版 CK3 新加的顶层层级：
  `h_china` / `h_india` / `h_roman_empire` / `h_eastern_roman_empire` /
  `h_dar_al_islam` / `h_kingdom_of_heaven`（共 6 个 ✓ `common/landed_titles/02_china.txt`
  那些文件里定义 ✓）。**它们不进编辑器的五级**（`TIER_ORDER` 不动、层级栈也不动 ✓），
  但**封君链会经过它们**：历史里 `liege = h_*` 有 **885 条** ✓
  ⚠ 不认 `h_` 的话，这些头衔压根进不了 `titles` → 解析历史时整条被丢掉 ✗
    → 那些封臣的链断在半路 → **全被判成独立** ✓（用户报的"东亚碎成一片、
    明明是封臣的被搞独立了"就是这个 ✓ 修完中华是一块 903 省的色块 ✓）
  所以：`_TITLE_RE` 认 `h_` ✓、`rank_titles` 里把 `h_` 跳过（不进层级栈 ✓）
  但**留在 `titles` 里给链走** ✓
- **男爵领常年没有 holder** → 那就是伯爵自己拿着 ✓ 所以判断从最细那层往上找
  "第一层有持有者的头衔" ✓（男爵领缺、拿伯爵领顶替过的那些地也走这条 ✓）
- 🔴 **封君只看历史里写没写** ✗ —— `history/titles` 把封臣关系**写全了**
  （本数据 4351 条 `liege` ✓ 而 1066 有持有者的头衔 5134 个 ✓）→
  **没写 = 独立** ✓ 就是这么读的 ✓
  ⚠ **不许拿"法理父级"当默认封君** ✗ —— 我试过一版（想修河西），结果用户当场抓到
  "**大辽吃掉了一堆蒙古帝国法理下的独立部落**" ✓ 法理 ≠ 封君：
  大辽法理上管着一大片草原，可 1066 那些部落各自独立 ✓
  拿法理当默认封君，整片草原就被吞进大辽 ✓（那一版还是错的 ✓ 已撤 ✓）
  河西那个是**另一件事**（同一个人的两块地 ✓ 见下面那条 ✓）
- 🔴 **同一个人手里的头衔算一个政权** ✗（按**持有者**归并 ✓）——
  西夏那位（角色 206651）**同时**拿着 `k_xia` 和 `k_hexi` ✓ 而他俩法理上的共同上级
  `e_yongliang` 在 1066 **没人持** ✗ → 链爬到那儿就断了 ✓ 于是"河西"和"夏"
  各自成一个政权 ✗（同一个人的两块地 ✓ 这才是用户报的那一条 ✓）
  归并之后：**国号取"层级最粗 → 法理地盘最大 → key"**（三级都比一遍 ✓ 稳定 ✓）
  → 西夏 = `k_xia`（法理 70 省，河西才 59 省 ✓ 他那 6 个直辖县也全在 k_xia 法理下 ✓）
  ⚠ 别拿"1066 那层的省份数"当尺 ✗ —— 那是自己刚算出来的结果，自我指涉
    （河西那版算出来反而更大 ✗ 国号会被叫成「河西」✓ 踩过 ✓）
  ⚠ 代价：同一个人手里"平级"的头衔会让归属**不是法理祖辈**（兄弟头衔 ✓）
    自检里那条"祖辈占比"因此在七成上下 ✓（下限放到 60% ✓ 见那条断言的说明 ✓）
- 🔴 **用了 obedience 的政府不算封臣** ✗（用户点名的："obedience 不算封臣" ✓）——
  新玩法里游牧（`nomad_government`）/ 草原行政（`steppe_admin_government`）走的是
  **"效忠"（obedience）**那一套 ✓ 它们之间不构成"封君—封臣" ✓
  判据在 `common/governments/*.txt`：块里（含 `government_rules` 嵌套 ✓）有
  `obedience = yes` 的政府 ✓（`parsers/ck3/parser.py` 的 `parse_governments` ✓）
  ⚠ 而 `history/titles` 里那些 `liege = e_great_liao` 是**没开 DLC 那套旧写法** ✗
    —— 乃蛮那份文件里 1040 那条上面自己写着注释 `# Liao Dynasty` ✓
    照它算的话整个草原都会被并进辽 ✗（用户报的"辽在乃蛮王国有领土" ✓ 已修 ✓）
  ⚠ `nomad_government` 本身也是 DLC 内容（`can_get_government = { has_mpo_dlc_trigger = yes }` ✓）
- **封君关系可以跨法理** ✗：本数据里约三成是这样（东亚那套官制 / 军镇最明显 ✓
  欧洲也有：爱沙尼亚的萨雷马伯爵在 1066 是利沃尼亚公爵的封臣 ✓ 法理上却不属于他 ✓）
  **是历史事实，不是 bug** ✓
- 这份 CK3（2026-10 那版）的 1066 数据跑出来是：**1173 个非封臣政权** ·
  **11297 块地全都有主** ✓（萨米、撒哈拉那些也有酋长/部落 ✓）
- **那会儿没人占的地 = 那一层直接留空**（`NO_TITLE`）✓ —— **跟 EU4 的无主地一个待遇** ✗
  不要给它造伪头衔、不要起名字、悬停也不要写一句"某某年无主" ✓（踩过：我一开始
  自作聪明加了个 `#unowned`「无主」节点 + 悬停文案，用户点名的"EU4 的无主地块
  直接没有标记，别发明新东西" ✓）。留空的效果本来就是对的：
  着色器里 `NONE` 画成那块灰（`gl.js` 里 `if (tid == NONE) return vec4(150,150,150,1)` ✓）、
  没有身份所以不参与认族、悬停链里那一级显示「（无」✓
- 🔴 **每个非封臣政权一个自己的节点** ✗（key = `1066_<原头衔 key>` ✓ 跟 EU4 那边
  `1444_FRA` 一个写法 ✓）—— 这才是"照搬代码"：
  · 剧本层的节点 **tier 必须是 0**（`ERA_TIER` ✓），前端拿它当「势力」那一层认 ✓
  · 取色匹配表 / `pidsOf` / 名字落点 / 悬停**全按"节点自己那一层"走** ✓
  ⚠ 我第一版图省事，让 1066 层**借用法理头衔的节点** ✗ —— 到处打结：
    取色表收不进（`tiers[] >= nEra` 全被挡 ✓）、站在地区层按 1066 的头衔涂会
    **涂不动**（`pidsOf` 是照节点自己的 tier 找行的 ✓）、名字落点也会跑到自家地盘外 ✓
- **节点顺序**：真头衔 → **1066 剧本节点** → 伪头衔（海/湖/荒地）✓
  ⚠ 剧本节点必须建在 `build_special_titles` **之前** ✗ —— 伪头衔的编号是
  `SPECIAL_BASE = 真头衔 + 剧本节点` 起的 ✓ 放在后面就会跟剧本节点**撞号**
  （我那版就是这样：670 块荒地的序号全挤进了真头衔范围 ✗ 自检当场抓住 ✓）
  `meta.numRealTitles` 也要把剧本节点算进去（它们不是伪头衔 ✓）
- **落点**：跟 `patch_wasteland.fix_label_positions` 同一把尺 ——
  **"像素最多的那块连通域的重心"**（照搬 `build_eu4.largest_block_centre` ✓）
  ⚠ 不能沿用那个顶层头衔的落点 ✗：1066 的地盘常常不等于法理地盘，
  借来的落点会跑到界外（自检里那条"名字落在自家地盘上"当场抓住 ✓）
- **它占的是层级栈第 0 层**（`ERA_TIER` / `MAP_ORDER` ✓）→ 法理那五层整体往后挪一位，
  所以 `defaultTier` / `labelZoom` / `titles.json` 里的 `tiers` 都跟着变 ✓
  所有下标**一律现查 `MAP_ORDER.index(...)`** ✗ 别再写死 4 / 3 ✓
- ⚠ **`patch_wasteland._detect` 的判定顺序也跟着改了** ✗ —— 它原来拿
  `"eraDates" in M` 认 EU5 ✓ CK3 一有剧本层就会被误认成 EU5、整份数据按 EU5 的规矩
  去刷名字 ✓ 现在先认 CK3 独有的 `deJureYear` ✓
- **「空白剧本」那一层也照搬了** ✓（用户点名的 ✓）：`build_data.py` 末尾跟别的
  构建器一样调一次 `patch_blank_era.patch(DATA)` ✓（幂等 ✓ 放在荒地之后 ——
  它照抄的是"最终这版"的背景地形 ✓）。链上从六层变七层：
  `1066 / 空白剧本 / 帝国 / 王国 / 公爵领 / 伯爵领 / 男爵领` ✓
  `defaultTier` 跟着 +1（还是伯爵领 ✓）· `eraDates` 变成两条（剧本块两格 ✓）
  ⚠ `patch_blank_era.DEFAULT_DIRS` 也把 `data`（CK3 那份）加进去了 ✓
    要单独补/重刷：`py patch_blank_era.py data` ✓
- **meta 里不多加字段** ✗ —— 层名就是「1066」（跟 EU4 那边「1444」一个写法 ✓），
  日期只写在文档和构建日志里 ✓（前端没有任何地方读它，加了就是自造字段 ✓）
- **自检**：`test_modes.js CK3` 里那一段「1a2. 1066 剧本地图那一层」——
  政权数（几百个，不是把封臣也各算一块 ✗）· 有头衔的陆地不会挂到海/湖/山伪头衔上 ·
  归属不比这块地自己更细 · 祖辈占比 ≥ 70% ✓（CK3 现在有 426 条断言 ✓
  因为别的模式那套"剧本层"玩法现在 CK3 也跑了 ✓）

## 拿开发版打开

在仓库根目录跑：

```bash
python server.py
```

然后开它给的地址。**不要**直接双击 `web/index.html` —— 浏览器不让 `file://`
去读那些 `.bin` 和瓦片分块，会白屏。

## 缓存里有什么

`data_*/` 是**从你自己安装的游戏**解析出来的：

- `meta.json`：地图尺寸、省份数、层级名、默认层、荒地节点、颜色表宽度等；
- `titles.json`：每个头衔节点的 key / 层级 / 父节点 / 名字 / 颜色 / 省份数 / 面积 /
  质心 / 标注位置 / 省份名 / 是否不显示地名；
- `titlemap.bin`：`(省份, 层级) → 头衔序号` 的映射（zlib 压过的 u16）；
- `provinces_id.bin`：像素 → 省份号；
- `tiles/`：分块的地图瓦片，单文件版会把它们 base64 内嵌。

## 地图包（导入式地图，2026-10-11 加）

**是什么**：一个 `.pdxmap` 文件（zip），里面就是一份 `data_xxx/` 加一个 `manifest.json`。
玩家在选图界面导入，它就成了列表里的一张新图，存在浏览器的 IndexedDB 里，刷新不丢。

⚠ **地图的"全部"数据都在包里**（2026-10-12 廿九点名确认过）：名字、颜色、层级、父级
（国家 / 地区 / 省份以及它们的颜色）都在 `titles.json`，归属在 `titlemap.bin`，
再加上省份号图 / 邻接 / 质心 / 分块 —— 一样都不缺，所以编辑器本体才敢一张都不内嵌 ✓
（`check_pack.js` 会逐个验"要发的包里名字和颜色都够数、颜色都在 0~255"；
 `check_standalone.js` 会拿包跟 data 目录逐项比头衔表 ✓）

⚠ **导入只增不改**（2026-10-11 按廿九的要求定的）：同 id 再导一次就是**新的一张**，
之前的一张都不动 ✓ 库里因此分两层身份 —— 记录的键是**实例键**
（第一份 = 作者写的 id，之后加 `~2`、`~3`……），`manifestId` 才是作者那个 id ✓
界面、涂色键、删除、导出**全认实例键**，别拿 `manifest.id` 当主键使 ✗
（唯一会问一句的是"逐文件 sha256 全等的那一份"，确认了也是新增 ✓）

**为什么**：mod 的图没拿到作者授权，不能内嵌进对外发的单文件（见 `app.js` 的 `MAP_CHOICES` 注释）。
有了地图包，图由作者自己打包、自己决定放不放出来，编辑器本体不需要出「适配某 mod」的版本。

**发布形态（2026-10-12 改的）**：编辑器本体**不内嵌地图**了 —— 一个约 0.8 MB 的 HTML
加 `packs/` 里那几个包（CK3 2.4 MB / EU4 0.8 / HOI4 1.4×2 / VIC3 3.6 / EU5 4.0 / EU5 原尺寸 12.3）✓
玩家要用哪张下哪张，在选图那一页导进去 ✓ 比以前"人人下 35 MB"划算得多 ✓
（全量版还留着：`python build_standalone.py --all-maps`，本地自用或特殊发布 ✓）

**完整设计、格式字段、验收标准**：[`docs/导入式地图-策划.md`](导入式地图-策划.md)。
改这块之前先读它 —— 尤其是「实测长度公式」和「实测必需字段」两节，
那些数是拿七个缓存目录量出来的，不要凭印象改。

四个新入口，改代码时对号入座：

| 想改什么 | 去哪 |
|---|---|
| 包里允许有什么、字段怎么校验 | `web/js/pack.js`（纯函数，Node 里能直接测） |
| 怎么读 zip、什么算"坏 zip" | `web/js/zip.js` 下半截（`readZip`） |
| 存哪、怎么新建/删除/导出备份 | `web/js/packstore.js` |
| 界面（导入入口 / 进度 / ⋯ 面板） | `web/js/app.js` 的 `pickMap` 那一段 |

```bash
python pack_map.py data_eu4 --id 我的图 --label "我的图" --author 我 --out 我的图.pdxmap
node tools/check_pack.js       # 校验器 + 好包坏包 + 公开 7 个包（81 条：含压缩炸弹、路径穿越、重名条目、分块几何、两端常量一致）
node tools/check_import.js     # 导入端一条龙（109 条：逐字节等价 / 只增不改 / 回滚 / 刷新不丢 / 备份往返 / 导两份互不影响 / 界面 / 分块包）
```

几条**别踩**的：

- **`.bin` 在包里是两层压**：zip 一层 + 里面那层 zlib ✓
  长度和内容要在**第二层**上算，而 `manifest.files` 的 sha256 是**第一层**（zip 里那份）的。
  搞反了所有包都会"哈希不对"（第一版就是这么错的）。
- **校验器只拒绝，不修数据**：读不出来就说清楚哪个文件哪儿不对，别替作者猜。
- **包里的字符串是陌生人写的**：label / note / author 一律 `textContent`，
  界面里别拼 `innerHTML`（`pickMap` 原来那处就是拼的，已经改了）。
- `packstore.js` 里**只能写行首的静态 import**：单文件版是拍平的，
  动态导入会原样留在产物里，`file://` 下必炸（`check_standalone.js` 有一条断言扫这个）。
- 新加的 js 文件要**同时**登记到两处：`build_standalone.py` 的 `MODULES` 和
  `tools/lib/browser_stub.js` 的 `MODULES`（顺序要一致）；
  `test_modes.js` 里还抄了一份自己的清单，也别忘了。

## 前端改动的注意点

- **`hidden` 属性必须真的能藏住** ✗ —— 这条吃过两次亏（2026-10-11）：
  自己写的 `.xxx { display: flex }` 权重比浏览器给 `[hidden]` 的 `display: none` 高，
  于是"加了 hidden 的元素照样杵在屏幕正中间，而且关按钮也是设 hidden，按了等于没按" ✓
  踩过的是**手机版的改名窗**和**导入地图包那个「⋯」面板**（都是玩家先发现的）。
  现在 `style.css` 顶部有一条兜底：`[hidden] { display: none !important; }` ✓
  **新加浮层/弹窗不用再单独补一条**，但也别去删那条兜底（`check_standalone.js` 有一条断言盯着它在不在）
  —— 另外注意：`app.js` 里 `el.hidden = true/false` 的语义一律是"藏/显"，
  没有那种"hidden 但靠 CSS 显示"的用法 ✓
- **手绘层（玩家涂色）的真相只有三样，而且都是"每个 province 自己"的** ✓：
  - `renderer.paintData[pid]` —— 这一格的颜色（alpha > 0 = 涂过）
  - `state.provLabel[pid]` —— 这一格的标记编号（名字在 `state.labelNames[编号]`）
  - `state.provTitle[pid]` —— 这一格是**哪一笔**涂的（最细层头衔序号，-1 = 没涂）

  其余全是**从这三样算出来的**：`state.painted` / `state.changed` 是缓存
  （`recomputePainted()` 逐格反推 ✓）；族 / 连通域 / 图例 / 标签 / 高亮 /
  撤销快照（`snapshotPidsList`）同理 ✓
  **别再按头衔存一份"颜色 / 名字 / 涂过没有"** ✗ —— 同一个头衔下的地块可以各是各的色
  （1936 那半壁法国就是这种），按头衔存就丢信息 ✓
  游戏数据那一侧同样是"每 province 的从属表"：`titlemap[层 × 省份数 + pid]` ✓
  所以"点一下该动哪些"（`paintTargetsAt`）也是从归属表现算的 ✓
  `state.paintColor` / `state.titleLabel` 是**旧的按头衔查表**（键是最细层头衔，
  等价于 province，不丢信息），新代码别往它们上面挂 ✗
- **名字（标签）数量有上限**：`rebuildPaintBlocks()` 末尾按**面积从大到小**只留前 N 个
  （`state.set.labelMax`，设置页「名字上限」，0 = 不限 ✓）。
  一个连通域一个名字之后全图能有几千坨（CK3 四千多），这一刀封在 `state.paintBlocks` ——
  标签层 / 图例 / 国名共用那一份，所以**一处封顶处处受益** ✓ 别在别处再截一次 ✗
- **设置页（`.modal#settings`）里的控件走同一套长相**：文字 / 数字 / 下拉 / 勾选 / range / color
  都在 `web/style.css` 的 `.set-row ...` 那一段里统一定义（字色 `--text`、边 `--line`、
  焦点 `--gold`、字号跟行里的标签一致 ✓）。
  **加新控件时别再让它顶着浏览器默认样式** ✗ —— 深色主题里会是一块白底，
  而且字号走浏览器默认（13~16px），跟旁边 11.5px 的标签不在一个调上 ✓
  （测试里有一条静态检查盯着这几类控件的样式在不在 ✓）
- 开关的默认值写死在两处：`web/index.html` 的勾选状态，和 `web/js/app.js` 里
  `applyGameText()` 内按模式的那一段（后者会覆盖前者，改默认值两边都要看）。
- 删掉任何界面元素时，**先把引用它的代码一并删掉**（`$('id')` 全局搜一遍）。
  测试里有一条断言专门盯着这件事：代码里取的元素必须真的在页面上。
- 着色器改动要注意 GLSL 的「先声明后使用」，测试里有源码顺序检查。
- **名单类字段一律走快查表**：`meta.wasteland` / `meta.degradedBaronies` /
  `meta.wasteAutoSkip` 这些名单，别在热路径上 `indexOf` 扫（悬停、每帧、每格都会撞上）。
  boot 时 `buildMetaIndex()` 会给它们建 `Set`，用 `isWastelandTid()` / `isDegradedBaron()` /
  `isWasteSkipPid()` 问。加新名单时记得一起进 `buildMetaIndex()`。
- **地块"身份"只有一处实现**：`paintIdentAt(pid, tier)`（显示名 + 显示色）。  认族、改名、涂色、图例都从它走 —— 以前 `playerGroupTidsAt` / `playerGroupPidsAt` /
  `paintIdentOf` 各写了一份几乎一样的，改一处得记得改三处。
  它**不能按头衔缓存**：同一个头衔底下的地块可以涂成不同色/不同标记。
- **诊断报告在 `web/js/log.js`**，是个**普通脚本**（挂 `window.PDXLOG`），不是 ES module ——
  它得**排在 app.js 前面**跑起来：编辑器自己没起来的时候，它是唯一还能记现场的东西 ✓
  拼接顺序写在**两处**（`build_standalone.py` 的 `MODULES`、`tools/lib/browser_stub.js` 的
  同名常量），加文件/挪顺序时一起改；漏改的话那套桩里没有 PDXLOG，
  app.js 一取就炸 —— 好在测试会当场喊出来 ✓
  界面上的接线有**三处**：顶栏「导出 ▾」里的 `#btn-log`、崩溃上屏框里那颗按钮（`showFatal`）、
  以及**启动页的 `#btn-boot-log`**（这一颗由 log.js 自己绑 —— app.js 没起来时它还得能用 ✓）。
  它拦 `console.error` / `console.warn`，**但原输出照旧转发** —— F12 里该怎么看还怎么看 ✓
- **诊断报告格式**（`log.js` 的 `text()`）：报告头（编号 / 时间 / 结论）→ `[1] 环境信息` →
  `[2] 运行状态` → `[3] 错误摘要` → `[4] 错误明细`（E-001 起，带严重级别 / 位置 / 栈 / 次数）→
  `[5] 事件时间线`（T-001 起，带相对毫秒）→ `[6] 附录`（`pdx-map-editor.diagnostic/2` 的 JSON，
  可被脚本直接解析）。改格式时**同时改 `tools/check_log.js` 的断言** —— 它盯着六节都在、
  JSON 能 parse、编号 / 错误数 / 事件数和正文一致。字段说明见
  格式说明已归档到本地资料，不作为公开文档。
- **涂抹 / 填色 / 橡皮共用同一个"这一下该动哪些地块"**：`paintTargetsAt(pid)` ✓
  剧本视图（+ 没开粒度 + 编辑层就在剧本那一层）下它给三条退路 ——

## 边界是怎么画的（改之前先看这一节）

> **2026-10-08 ~ 10-10 重做过一轮**：原来每个像素、每帧都要**沿四个方向走射线**找边界，
> 缩小时半径能到 10 格 → 几百次纹理采样/像素/帧（用户报的"缩放超级无敌卡"）。
> 现在**加载地图时先算一张 1 位/格的粗筛位图**，每帧先取一位：
> `0`（一辈子画不到线，约 85%）→ **直接退出**；`1` → 才走射线，而且**射线跳步**
> （步长 ≈ 半个屏幕像素跨的地图格数，缩小时步数不再随缩放涨）。
> 边界相关纹理内存 **88MB → 1.4MB**，换层 / 涂色 **零重算**。
> 三条判据是用户点破的：**上级不新增边界**（任何层的边界都落在省界上 → 位图只跟省份图
> 的**形状**有关、跟当前层和涂色无关 ✓）· **离边界 2 格和 3 格没区别**（都不画 → 1 位
> 就够，不需要距离）· **加载时顺便算完**（所以换层 / 涂色都不用重算）。
> ⚠ 试过又**删掉**的路（别再走）：布尔掩码凑距离（丢方向 → 放大出"梯子"）、
> 浮点距离场 RGBA8（44MB，且和多级链叠在一起时线宽乱）、等级图（11MB，比位图大 8 倍
> 而精度用不上）。**现在只有一条预计算：那张 1 位位图。**

## 动着色器 / 纹理的硬规矩（2026-10-10 血泪换的）

这几轮白屏黑屏了**四次**，每次都是同一类"改了一处忘了另一处"。四条已经做成断言，
**别再绕过它们**：

1. **每个采样器都必须指向一张完整纹理** ✗ —— 这是 WebGL 的硬规矩，**哪怕那条分支根本
   不采样它** ✓ 违反的后果是 `drawArrays` 报 **`INVALID_OPERATION`(1282)** → **整帧被
   丢弃 → 屏幕全黑**，而且**不抛异常、控制台什么都没有**（最难查的一种 ✓）。
   手机黑屏那次就是：着色器声明了 `sampler2D uBorderDepth`，而手机上**不建那张位图**，
   `render()` 的 `else` 分支只把 `uBorderDepthOn` 设成 0、**纹理单元上什么都没绑** ✗。
   修法：关掉某一路时，也给它绑一张 **1×1 占位纹理**（`this.dummyTex`）✓
   电脑上没事是因为那张图建得出来、绑上了 → **"电脑行、手机不行"多半就是这类** ✓

2. **纹理格式和 sampler 声明必须配对** ✗ —— 归一化（`R8`/`RGBA8`）配 `sampler2D`，
   整数（`R8UI`/`R16UI`）配 `usampler2D` ✓ 配错的报错是
   `no operation exists that takes 'highp uint' and 'const float'` ✓

3. **循环上界必须是常量** ✗ —— `for (int i = 0; i < 4; i++)` + 里面 `break` ✓
   别图"少让编译器展开、编译快一点"写成 `i < uSomeUniform` —— 规范上 GLSL ES 3.0 允许，
   **但手机驱动不认** ✗ → 着色器编译不过 → 黑屏 ✓

4. **改完着色器，桩是测不出来的** ✗（`tools/lib/browser_stub.js` 里没有真 WebGL）✓
   所以静态守卫必须全绿：大括号 / 小括号配平 · 声明顺序 · 格式↔声明配对 · 循环上界。
   真出问题只能靠真机 —— 手机版上留了**启动里程表**（`bootMark` ✓ 左上角绿字），
   它一路打点：`①开始建 → ①到渲染器 → ②着色器OK → ③传数据前[GL上限/地图/画布] →
   ④数据OK → ⑤算粗筛前 → ⑥算粗筛后 → ⑦就绪 → ⑧进帧循环 → ⑨遮罩已藏[画布/CSS/中心像素/出错码]`
   —— **停在哪一段、出错码是几，直接指向病因** ✓（排查时优先读 `readPixels` 的中心像素
   和 `getError()`：像素黑 = 真没画出来 ✗，像素有色却屏幕黑 = 显示/合成层的问题 ✓）

## 切后台回来黑屏：上下文丢失与恢复（2026-10-11 加）

手机切出去（看别的 App / 锁屏 / 切标签页）再回来，画面是黑的。**这是必然会发生的事** ✓：

- 手机会把 **WebGL 上下文整个收走**（省显存，iOS 尤其积极 ✓），一切 GL 对象随之作废 ✓
- 以前只接了 `webglcontextlost`（还 `preventDefault()` 了 ✓）**却没接 `webglcontextrestored`** ✗
  → 回来时上下文是好的、**显存里空着**、`dirty` 还是 `false` → **再也不画** ✓ → 一直黑 ✓
  （顺带一提：`toast` 是关着的 `TOAST_OFF`，所以那时候连"请刷新"都看不到 ✓）

现在这条路是**通的**，分工写死如下：

| 谁 | 干什么 |
|---|---|
| `gl.js` 的 `_build()` | 建"跟上下文绑在一起"的那些：着色器 / uniform 位置 / VAO / 1×1 占位纹理。**可以重复调用** ✓ |
| `gl.js` 的 `restored` 监听 | 调 `_build()` + 把全部纹理引用清成 `null`（旧的都废了 ✓）+ 叫 app 那边重喂 |
| `app.js` 的 `uploadMapToGpu()` | 把**数据**重新喂一遍：省份 id / 归属表 / 颜色 / 荒地 / 手绘层 / 设置 ✓ |
| `app.js` 的 `reuploadTiles()` | 分块那条路（EU5 原尺寸）：把 `tileMap.cache` 里的块重传 ✓ 不用重新下载解压 |
| `app.js` 的 `onEnterForeground()` | 回前台：重量画布尺寸 + **强制重画一帧**；上下文没回来就等 3 秒，还不回来才明说"刷新能重来" |

两条**不能破**的规矩：

1. **`setData()` 重跑时不许重建 `paintData` / `paintLabelData` / `lutData`** ✗ ——
   它们**不是 GL 资源**，是 CPU 那边的真相 ✓ 里面装的是用户涂的东西 ✓
   无脑重建 = "切个后台回来，涂的全没了" ✓（现在按"长度对得上就留着、标个脏"处理 ✓）
2. **`dirty` 为 false 时 `render()` 连 `resize()` 都不跑** ✓ —— 所以"回来重画一帧"这件事
   必须由 `onEnterForeground()` 主动做 ✗ 不能指望帧循环自己醒过来 ✓

自检里已经钉住了（`check_standalone.js` / `check_mobile.js`）：派一发 `webglcontextlost` 停画 ✓、
派一发 `webglcontextrestored` 数据得回来 ✓、**笔迹一格都不许少** ✓、回前台必须重画 ✓。

### 启动时的上下文丢失：别再报成"着色器编译失败"（2026-10-17）

用户 / 管理员报「打开就莫名其妙着色器连接失败」，真凶常常是 **WebGL 上下文在创建后丢了**：

- 上下文一丢，`createShader` / `compileShader` **静默 no-op** → `COMPILE_STATUS` 返回 false
  → 老代码下一句就 `throw '着色器编译失败'`，日志还是空的 ✗
- 顶部 `boot()` 的 `catch` 又把 `new MapRenderer()` 的**任何**异常都盖成同一句 ✗

## 手机版怎么出
**桌面版和手机版共用同一套源码** ✓ 区别只有"打不打 `mobile/` 里那层补丁"：

```bash
python build_standalone.py     # 出桌面版 → pdx-map-editor.html（**轻量版**，约 0.8 MB）
python mobile/build.py         # 出手机版 → pdx-map-editor-mobile.html
```

⚠ **单文件默认不内嵌地图**（2026-10-12 起）✗ 地图改成 `.pdxmap` 包单独发：
`python build_packs.py` → `packs/` 里 **7 个公开包**（约 27 MB），跟那个约 0.8 MB 的 HTML 一起传 Release 附件 ✓
⚠ **CK2 还在内测，默认不打进 `packs/`** ✗；要打内测包只能：
`python build_packs.py --include-private --out _local/packs-internal`，**不许上传** ✓
要"一个文件全都有"的全量版就加 `--all-maps`（35 MB，本地自用 / 特殊发布用）✓
两边的地图清单**只有一份**（`build_standalone.py` 的 `MAPS`），别在别处再抄 ✗

`mobile/` 里放着：

| 文件 | 是什么 |
|---|---|
| `mobile_css.txt` | 手机端样式，追加到 `web/style.css` 末尾 |
| `mobile_js.txt` | `bindMobile()`：一级六入口 + 二级下拉面板 + 触摸手势，插在 `bindEvents()` 前面 |
| `mobile_html.txt` | 启动页里那点注释（界面是 `bindMobile()` 运行时造的 ✓） |
| `patch.py` | 打补丁 / 退补丁（手动用才需要） |
| `build.py` | 一键：打补丁 → 烤单文件 → 改名 → **源码按字节还原** |

两个要点：

- `build.py` 开工前会拍**两个字节快照**（电脑版文件 + `web/` 三个源文件），收工原样写回。
  所以它**绝不会覆盖电脑版**，也不会弄丢你没提交的源码改动 ✓
- 手动 `python mobile/patch.py revert` 走的是 `git checkout`，所以要求那三个文件
  **没有未提交的改动** —— 有的话它会拒绝执行并提示你改用 `build.py` ✓

`check_standalone.js` **两种形态都认**：产物里没内嵌地图（轻量版）时，
它会先导一个 `packs/` 里的包再点进去 —— 那正好是玩家第一次用的完整路 ✓
（所以轻量版这条跑之前得先有 `packs/`，没有就 `python build_packs.py` ✓）

`check_mobile.js` 比电脑版那个多验两件事，都是手机版独有的坑：

- **补丁到底打进去没有**：`#mob-ui` 在 CSS 里、`function bindMobile` 在 JS 里、
  `bindMobile()` 那个启动挂点在不在、**而且只有一份**（重复打会叠一份 CSS ✗）；
- **打进去之后还跑不跑得起来**：补丁是在 `bindEvents()` 前面插一大段 + 在启动流程里插一句，
  锚点变了或者插歪了就是"一启动就抛、白屏" —— 它会真跑一遍 `boot()` 看能不能到「就绪」。

`mobile/` 那三块补丁**只碰界面**（造按钮、搬现成节点、接触摸手势），
内部函数只调通用的那几个（`actAt` / `setTool` / `setTier` …），
所以改 `app.js` 内部实现一般不影响它；但**锚点那条不能动**：
`function bindEvents() {` 和 `    bindEvents();` 各只能出现一次，`<footer class="statusbar">` 同理。

手机版的界面结构（改 UI 时先看这个）：

- **一级**：地图 + 顶栏（`←` 回主菜单 · 永夜廿九 · `↶ ↷` 撤销重做 · 教程 · 文件）+ 底部四个入口
  （设置 / 颜色 / 工具 / 视图；「工具」那个按钮上写的是**当前工具名**）
- **二级**：点某个入口 → 从**那个按钮正上方**弹出一栏（带指向按钮的小尖角；按钮在上半屏就往下弹）
- **设置**那一栏 = 一排标签（显示 / 颜色 / 边界 / 导出图例）+ 下面跟着换内容；
  高度在打开时按**最高那页**锁住 ✓ 切标签不跳
- **触摸**：单指按住拖动 = 连续涂色（自己驱动 `actAt`，不等浏览器的合成鼠标事件）；
  轻点 = 涂一块；长按 = 右键取色（只取色，不会先涂一块）；双指 = 平移 + 缩放
  （缩放是合成一个**真实的 wheel 事件**，所以教程判定和缩放逻辑都复用现成的）
- **回主菜单**（顶栏 `←` / 电脑版右上角按钮 / `Esc`）= 重新加载页面回到选地图那一页；
  走之前会把涂色写进 localStorage 暂存（**按地图分开存**），再选同一张图会自动接上 ✓
