# 构建与开发说明

> 这份是给**想自己生成数据 / 改代码**的人看的。只想玩的话看根目录的 `README.md` 就够了。

## 需要什么

- **对应游戏的安装**：Steam 版会自动定位；找不到（或装在别处）就用参数手动指。
  解析器读的是安装目录里的地图和本地化文件。
- **Python 3.10+** 和 `numpy`。
- EU4 想显示中文国名，还需要汉化 mod（脚本会在 workshop 目录里自动找）。
- 改前端不需要任何构建工具：原生 JS，改完刷新即可。

## 生成数据

单文件版已经把数据烘进去了；只有换地图、换游戏版本、改解析时才需要这一步。

```bash
python build_data.py                       # CK3       → data/
python build_data.py --map <另一套图的 provinces.png> --out data_xxx --label "自定标签"
python build_eu4.py                        # EU4       → data_eu4/
python build_eu4.py --mapdir <另一套图的 map 目录> --out data_xxx --label "自定标签"
python build_hoi4.py                       # HOI4      → data_hoi4/
python build_hoi4.py --provinces <改过边界的 provinces.bmp> --out data_hoi4_alt --label "HOI4 修改边界"
python build_vic3.py                       # Victoria3 → data_vic3/
python build_eu5.py                        # EU5       → data_eu5/
python patch_wasteland.py                  # 荒地后处理（各构建脚本末尾会自动调用）
python patch_blank_era.py                  # 补一层「空白剧本」（同上，末尾自动调用；幂等）
python patch_waste_pseudo.py               # 把荒地挪成伪头衔（EU5 需要；同上，末尾自动调用；幂等）
python build_standalone.py                 # 把所有 data_*/ 烘成一个单文件 HTML
```

常用参数（`--help` 看全部）：

| 参数 | 说明 |
|---|---|
| `--ck3 / --eu4 / --hoi4 / --vic3 / --eu5 <目录>` | 手动指定安装根目录 |
| `--out <目录>` | 缓存写到哪（默认 `data_*`） |
| `--label <名字>` | 这套地图在顶栏「地图」里的显示名 |
| `--map <图片>` / `--mapdir <目录>` | 换一套地图文件（另一套 provinces.png / map 目录） |
| `--lang <语言目录>` | CK3 本地化语言，默认 `simp_chinese` |
| `--no-history` / `--no-dejure-history` | 不读历史文件，快很多，但年份层会变粗 |

## 拿开发版打开

在仓库根目录跑：

```bash
python server.py
```

然后开它给的地址。**不要**直接双击 `web/index.html` —— 浏览器不让 `file://`
去读那些 `.bin` 和瓦片分块，会白屏。

## 缓存里有什么

`data_*/` 是**从你自己安装的游戏**解析出来的：

- `meta.json`：地图尺寸、省份数、层级名、默认层、荒地节点、颜色表宽度等；
- `titles.json`：每个头衔节点的 key / 层级 / 父节点 / 名字 / 颜色 / 省份数 / 面积 /
  质心 / 标注位置 / 省份名 / 是否不显示地名；
- `titlemap.bin`：`(省份, 层级) → 头衔序号` 的映射（zlib 压过的 u16）；
- `provinces_id.bin`：像素 → 省份号；
- `tiles/`：分块的地图瓦片，单文件版会把它们 base64 内嵌。

```bash

```

每个模式约 220～350 条断言，覆盖：数据完整性、层级与标签缩放、六组开关的解析、

## 另外几把工具（`tools/`）

`test_modes.js` 验的是"行为对不对"。另外几件事各有一把尺子，都在 `tools/` 下：

```bash
node tools/check_standalone.js        # 烤好的电脑版单文件能不能跑（改完记得重烤再跑它）
node tools/check_mobile.js            # 烤好的手机版：补丁在不在 + 打完还跑不跑得起来
node tools/check_log.js               # 报错日志模块本身：收得到 / 记得住 / 导得出
node tools/bench_core.js VIC3         # 核心路径性能基线（4 万地块那张最看得出差别）
python tools/fix_comments.py --dry    # 注释里被吞掉的中文标点，看一遍会改哪几处
```

- **`check_standalone.js`** —— 这是**唯一**一条真正验证发布产物的路。
  它把 `pdx-map-editor.html` 里的内嵌数据和拍平脚本原样抠出来，
  用同一套假 DOM / 假 WebGL 跑一遍 `boot()`：七套地图的 meta 与头衔表解得开吗、
  渲染器建得起来吗、换一张图还能起来吗。以前没人打开过那个 35 MB 的文件检查，
  烤坏了只有"玩家双击、白屏、来问你"这一条路能发现。
- **`bench_core.js`** —— 只管掐表，不验行为。量的都是"每帧 / 每点一次都在跑"的东西：
  `rebuildPaintBlocks`（涂一笔之后重算色块）、`playerGroupPidsAt`（填色·边界下点一下认族）、
  帧里的同步三连。**改性能之前先跑一次存着**，改完再跑，不然"快了还是慢了"全靠感觉。
- **`fix_comments.py`** —— 见下面「注释里的吞字」那一节。

性能这块另外还有两把**临时尺子**（做完那次优化留下的，以后动热路径可以再用）：

```bash
PDX_BEFORE=/path/to/旧源码 node tools/exp_repeat.js VIC3 7   # 重复测量：均值±标准差，判定差值可不可信
PDX_BEFORE=/path/to/旧源码 node tools/exp_unionfind.js VIC3  # 专量"并查集那一遍"的中间表改动
node tools/probe_blocks.js VIC3                              # 专查"细层重分组会不会并出巨组 / 变 O(n²)"
node tools/exp_whatif.js EU5                                 # 逐条拆开量（含荒地名录 Set 快查）
```

`exp_repeat.js` 里那条判定值得记住：**差值必须大于两边标准差之和才算结论**。
不然就会像我第一轮那样，拿单次抖动读出个"CK3 的认族慢了 18%" —— 而那段代码我压根没动。

三把工具和 `test_modes.js` 共用同一套浏览器桩（`tools/lib/browser_stub.js`）：
假 DOM、假 Canvas2D、假 WebGL、假 localStorage、假 fetch、按单文件版顺序拍平源码。
**新加工具请 `require` 它**，别再抄一份 —— 抄一份的结果已经出现过了：
DOM 桩在一处补了 `elementFromPoint`、另一处没补，那边就在图例拖动那一步炸掉。

（`check_log.js` 是**故意不 require 它**的那一个：日志模块要能在
"编辑器整个没起来"的时候照样工作，所以那边给的是一个最小的假 window ——
依赖越少，越接近它真正要顶事的那种场合 ✓）

## 前端改动的注意点

- **手绘层（玩家涂色）的真相只有三样，而且都是"每个 province 自己"的** ✓：
  - `renderer.paintData[pid]` —— 这一格的颜色（alpha > 0 = 涂过）
  - `state.provLabel[pid]` —— 这一格的标记编号（名字在 `state.labelNames[编号]`）
  - `state.provTitle[pid]` —— 这一格是**哪一笔**涂的（最细层头衔序号，-1 = 没涂）

  其余全是**从这三样算出来的**：`state.painted` / `state.changed` 是缓存
  （`recomputePainted()` 逐格反推 ✓）；族 / 连通域 / 图例 / 标签 / 高亮 /
  撤销快照（`snapshotPidsList`）同理 ✓
  **别再按头衔存一份"颜色 / 名字 / 涂过没有"** ✗ —— 同一个头衔下的地块可以各是各的色
  （1936 那半壁法国就是这种），按头衔存就丢信息 ✓
  游戏数据那一侧同样是"每 province 的从属表"：`titlemap[层 × 省份数 + pid]` ✓
  所以"点一下该动哪些"（`paintTargetsAt`）也是从归属表现算的 ✓
  `state.paintColor` / `state.titleLabel` 是**旧的按头衔查表**（键是最细层头衔，
  等价于 province，不丢信息），新代码别往它们上面挂 ✗
- **名字（标签）数量有上限**：`rebuildPaintBlocks()` 末尾按**面积从大到小**只留前 N 个
  （`state.set.labelMax`，设置页「名字上限」，0 = 不限 ✓）。
  一个连通域一个名字之后全图能有几千坨（CK3 四千多），这一刀封在 `state.paintBlocks` ——
  标签层 / 图例 / 国名共用那一份，所以**一处封顶处处受益** ✓ 别在别处再截一次 ✗
- **设置页（`.modal#settings`）里的控件走同一套长相**：文字 / 数字 / 下拉 / 勾选 / range / color
  都在 `web/style.css` 的 `.set-row ...` 那一段里统一定义（字色 `--text`、边 `--line`、
  焦点 `--gold`、字号跟行里的标签一致 ✓）。
  **加新控件时别再让它顶着浏览器默认样式** ✗ —— 深色主题里会是一块白底，
  而且字号走浏览器默认（13~16px），跟旁边 11.5px 的标签不在一个调上 ✓
  （测试里有一条静态检查盯着这几类控件的样式在不在 ✓）
- 开关的默认值写死在两处：`web/index.html` 的勾选状态，和 `web/js/app.js` 里
  `applyGameText()` 内按模式的那一段（后者会覆盖前者，改默认值两边都要看）。
- 删掉任何界面元素时，**先把引用它的代码一并删掉**（`$('id')` 全局搜一遍）。
  测试里有一条断言专门盯着这件事：代码里取的元素必须真的在页面上。
- 着色器改动要注意 GLSL 的「先声明后使用」，测试里有源码顺序检查。
- **名单类字段一律走快查表**：`meta.wasteland` / `meta.degradedBaronies` /
  `meta.wasteAutoSkip` 这些名单，别在热路径上 `indexOf` 扫（悬停、每帧、每格都会撞上）。
  boot 时 `buildMetaIndex()` 会给它们建 `Set`，用 `isWastelandTid()` / `isDegradedBaron()` /
  `isWasteSkipPid()` 问。加新名单时记得一起进 `buildMetaIndex()`。
- **地块"身份"只有一处实现**：`paintIdentAt(pid, tier)`（显示名 + 显示色）。  认族、改名、涂色、图例都从它走 —— 以前 `playerGroupTidsAt` / `playerGroupPidsAt` /
  `paintIdentOf` 各写了一份几乎一样的，改一处得记得改三处。
  它**不能按头衔缓存**：同一个头衔底下的地块可以涂成不同色/不同标记。
- **报错日志在 `web/js/log.js`**，是个**普通脚本**（挂 `window.PDXLOG`），不是 ES module ——
  它得**排在 app.js 前面**跑起来：编辑器自己没起来的时候，它是唯一还能记现场的东西 ✓
  拼接顺序写在**两处**（`build_standalone.py` 的 `MODULES`、`tools/lib/browser_stub.js` 的
  同名常量），加文件/挪顺序时一起改；漏改的话那套桩里没有 PDXLOG，
  app.js 一取就炸 —— 好在测试会当场喊出来 ✓
  界面上的接线只有两处：顶栏「导出 ▾」里的 `#btn-log`，和崩溃上屏框里那颗按钮（`showFatal`）✓
  它拦 `console.error` / `console.warn`，**但原输出照旧转发** —— F12 里该怎么看还怎么看 ✓
- **涂抹 / 填色 / 橡皮共用同一个"这一下该动哪些地块"**：`paintTargetsAt(pid)` ✓
  剧本视图（+ 没开粒度 + 编辑层就在剧本那一层）下它给三条退路 ——
  **玩家涂色归属（全图同色同标记）→ 剧本归属（那一国里同色同标记）→ 最低单位那一块**
  （"两个边界开关都没开"按填色开着算；这段规则写在那个函数头上 ✓）。
  细层则是"`tid` 那一块底下的地块" ✓
  ⚠ **"归属" = 标记 + 颜色**（用户特意强调过 ✓），不是"整个头衔"：
  同一个国家里被涂成别的颜色的地方颜色对不上，**一块都不该碰** —— 所以 ② 用的是
  `sameBlockPids(tid, pid)`（本层头衔内同色同标记），不是 `pidsOf(tid)` ✗
  涂色（`paintAt`）和还原（`actAt` 的 erase 支线）**都调它**，别再各写一份 ✗ ——
  以前两处各一套，改一处忘一处；`paintPidsAsOne` 负责"一次点击 = 一条撤销" ✓
  **悬停高亮也是这一套**（用户要求 ✓）：`applyHoverHighlight` → `hoverGroupRgb` ——
  涂过的地按族（着色器 `uHoverPaintOn` + 颜色 + 标记），其余按编辑层头衔
  （`uHoverTid` 配 `uEditTier`）✓ 三处口径要一起改，别只改一处 ✗
  两个历史坑：① 还原那支原来把这块地在**所有层级**上的头衔全捞出来清 →
  在省份层点一下就把整块**地区**清空（用户报过；`test_modes.js` 3c-2 是它的尺子 ✓）；
  ② 挑测试对象要**筛掉伪头衔**（海 / 湖 / 荒地各层共享，`tiers[tid]` 落在 `TIER_COUNT`
  之外，`syncPaint` 直接拒绝）—— 挑到它就会出现"一个省都涂不上"的假失败 ✓

## 边界是怎么画的（改之前先看这一节）

> **2026-10-08 ~ 10-10 重做过一轮**：原来每个像素、每帧都要**沿四个方向走射线**找边界，
> 缩小时半径能到 10 格 → 几百次纹理采样/像素/帧（用户报的"缩放超级无敌卡"）。
> 现在**加载地图时先算一张 1 位/格的粗筛位图**，每帧先取一位：
> `0`（一辈子画不到线，约 85%）→ **直接退出**；`1` → 才走射线，而且**射线跳步**
> （步长 ≈ 半个屏幕像素跨的地图格数，缩小时步数不再随缩放涨）。
> 边界相关纹理内存 **88MB → 1.4MB**，换层 / 涂色 **零重算**。
> 三条判据是用户点破的：**上级不新增边界**（任何层的边界都落在省界上 → 位图只跟省份图
> 的**形状**有关、跟当前层和涂色无关 ✓）· **离边界 2 格和 3 格没区别**（都不画 → 1 位
> 就够，不需要距离）· **加载时顺便算完**（所以换层 / 涂色都不用重算）。
> ⚠ 试过又**删掉**的路（别再走）：布尔掩码凑距离（丢方向 → 放大出"梯子"）、
> 浮点距离场 RGBA8（44MB，且和多级链叠在一起时线宽乱）、等级图（11MB，比位图大 8 倍
> 而精度用不上）。**现在只有一条预计算：那张 1 位位图。**

一共**三遍**，按顺序叠上去，后画的压前面的。线色都一样（深蓝黑 `0.035,0.045,0.06`），
只有宽度和浓度不同。
**粗筛**：一位定生死（见上）；射线只在"这一位是 1"时才跑，步长随缩放跳。
搜索半径 `R = ceil(0.5 × 每屏幕像素代表的地图像素数 × (本层宽与填色宽里较大的 + 1))`；
只要这一格**是个地块**（`provAt != 0`）就参与计算 —— **无主地也算地**，
它跟国家之间那条边、它跟海之间那条海岸线都要画 ✓
（早先是 `tidAt(ip) != NONE`，而无主地拿到的正是 NONE，于是"国家 ↔ 无主地"
只剩国家那半边有线、无主地海岸线整条没有 ✗）。

| 这一遍 | 看哪一层 | 拿什么比 | 听哪个开关 |
|---|---|---|---|
| 基础层（本层） | 编辑层（开了粒度就是粒度那层） | 那一层的**头衔 id** | CK3：头衔·边界；年代模式：年份层听「势力·边界」，更细的层听「地区·边界」 |
| 父级链（最多 4 级） | 逐级往上的地理层 | 那一级的**头衔 id** | 同上，逐级各听各的 |
| 填色层 | 逐像素 | 剧本/国家那层按**当前显示颜色**；**细层与 CK3 只比手绘层** | 填色·边界（**哪一层都画** ✓） |

「海与海之间不画线」那条判据里**要把无主地排除**：`NONE` 是地、不是地形，
不然无主地挨着海那条海岸线会被一起吃掉 ✗。

**「爷爷级」这个词指的是玩家填色的那条线**，不是更高的地理单位 —— 它占链上最粗那一级。

**宽度与浓度**（`baseW` = 基准线宽，只在启动时记一次，之后不被自己改动的值污染）。
浓度只剩三档，全部来自设置页：省份档 `pa`、地区档 `ra`、**势力档 `ca`**：
（`ca` 这一档在设置页显示成「**势力边界浓度**」（原来叫「涂色边界浓度」）；
字段名故意不改 —— 存档/配置里存的就是 `ca` ✓）

- 本层（子级）：**浓度一律省份档、宽一律细档** ✓（细档 = 粗细阶梯里的"本层 1"那格 ×
  「基准线宽 / 1.6」，跟「父级边界」开不开无关 ✓）——
  以前浓度还分过一档「默认边界浓度」（`da`，没开「父级边界」时用它，75）✗，
  现在这一档**整个去掉了**（设置页那一行也删了 ✓）：子级那条任何时候都是省份档 50 ✓，
  「父级边界」这个开关只管**链本身画不画**，不再改本层的浓淡 ✓
  （旧存档里残留的 `da` 字段会被忽略，不会再把本层压回 75 ✓）
  **例外**：本层要是"势力那一层"（`editTier() < 年份层数`，也就是国家/tag 那一圈）
  → 浓度与宽度都按**势力**那套（浓度势力档、宽 = 最粗那格 × 势力线宽）✓，
  不再走省份档。判的是**编辑层**不是视图层：
  开着粒度时本层是粒度那一层（省份之类），仍旧走上面那套 ✓
- 链上每一级：宽 `baseW × 0.75 + 0.25 × (k+1)`（一层粗 0.25）；浓度 = **年代那一圈吃势力档、
  其余父辈吃地区档**。
- 填色层：宽 `max(baseW × 0.75 + 0.50, 链上最粗, baseW + 0.25)` —— **下限是爷爷档**；
  浓度恒 **势力档**。
- **水域线**（海/湖/河 ✓）**和荒地线**：一直画，**当前模式里能关的边界全关了**才跟着藏 ✓
  （有年代层：势力 / 地区 / 填色 三个；CK3：头衔 / 填色 两个 —— 那两组国家边界在 CK3 是隐藏的 ✗
   判据写在 syncLayerSwitches() 里，别写死那三个名字 ✗）；
  浓度和宽度都**各自可调**（设置页「水域边界宽度 / 水域边界浓度」✓ 没有单独的显示开关 ✗）。
- **荒地线**：宽度与浓度也是**自己一套** ✓（设置页「荒地边界宽度 / 荒地边界浓度」✓
  着色器里 `uWasteW` / `uWasteA`；以前借填色边界那两个值 ✗ 用户要求拆开 ✓）。
  范围是**所有**带荒地的缝：荒地↔国家 ✓、荒地↔荒地 ✓、荒地↔无主地 ✓
  —— 本层 / 多级边界那几趟一律把这些缝让出来 ✗（不然看着又变成子级的宽浓 ✗）；
  荒地 ↔ 水归水域线 ✓（`rayDistTitle` 里先按水岸线 break ✓）。
  **⚠ 被涂过色的荒地不算荒地** ✓（用户定的）：判据是
  `wasteAlphaOf(那一格) > 0.5 && paintAt(那一格).a < 0.5` ——
  荒地一涂上色，它就是你的版图了，边界按**普通地块**走（本层那条线 + 本层的宽浓）✓
  （`rayDistTitle` 里两处判据要一起改 ✗ 只改一处会两套口径打架 ✓）。

**链怎么来**：CK3 只描父级一层；年代模式从「粒度 −1」数到年代层，再加年代层自己（最多 3 级）。
「父级边界」关掉 → 链清空，但"本来会有上两级"这件事记着，本层仍旧压淡。

**分组/身份用的颜色一律是"稳定色"**（涂过用涂色，否则用头衔自己的颜色），
**不能**跟显示开关走 —— 否则一关「头衔·颜色」，原版国家全变成背景灰，
和玩家涂的同名色块分成两组，同一个国家会冒出两个名字。
涂色实体的身份是**名字优先**：名字相同就是一家，颜色不同也不分家；没名字的纯色块才按颜色分。

**名字落点：一个连通域一个**（`rebuildPaintBlocks` ✓）。同色同标记的并查集切出来多少坨，
就出多少个标签，每个标在**那一坨自己**的几何中心上，字号也按**那一坨自己的面积**给
（小岛够不上门槛就不画 ✓）。

数据首都（`meta.capitals` → 国名 → 首都省）、本土（`state.homelandOf`）——
三条路抢一个落点，还得跟涂色、改名、导入清名打配合（`eraNameOf` 那份留底就是为它留的）。

## 动着色器 / 纹理的硬规矩（2026-10-10 血泪换的）

这几轮白屏黑屏了**四次**，每次都是同一类"改了一处忘了另一处"。四条已经做成断言，
**别再绕过它们**：

1. **每个采样器都必须指向一张完整纹理** ✗ —— 这是 WebGL 的硬规矩，**哪怕那条分支根本
   不采样它** ✓ 违反的后果是 `drawArrays` 报 **`INVALID_OPERATION`(1282)** → **整帧被
   丢弃 → 屏幕全黑**，而且**不抛异常、控制台什么都没有**（最难查的一种 ✓）。
   手机黑屏那次就是：着色器声明了 `sampler2D uBorderDepth`，而手机上**不建那张位图**，
   `render()` 的 `else` 分支只把 `uBorderDepthOn` 设成 0、**纹理单元上什么都没绑** ✗。
   修法：关掉某一路时，也给它绑一张 **1×1 占位纹理**（`this.dummyTex`）✓
   电脑上没事是因为那张图建得出来、绑上了 → **"电脑行、手机不行"多半就是这类** ✓

2. **纹理格式和 sampler 声明必须配对** ✗ —— 归一化（`R8`/`RGBA8`）配 `sampler2D`，
   整数（`R8UI`/`R16UI`）配 `usampler2D` ✓ 配错的报错是
   `no operation exists that takes 'highp uint' and 'const float'` ✓

3. **循环上界必须是常量** ✗ —— `for (int i = 0; i < 4; i++)` + 里面 `break` ✓
   别图"少让编译器展开、编译快一点"写成 `i < uSomeUniform` —— 规范上 GLSL ES 3.0 允许，
   **但手机驱动不认** ✗ → 着色器编译不过 → 黑屏 ✓

4. **改完着色器，桩是测不出来的** ✗（`tools/lib/browser_stub.js` 里没有真 WebGL）✓
   所以静态守卫必须全绿：大括号 / 小括号配平 · 声明顺序 · 格式↔声明配对 · 循环上界。
   真出问题只能靠真机 —— 手机版上留了**启动里程表**（`bootMark` ✓ 左上角绿字），
   它一路打点：`①开始建 → ①到渲染器 → ②着色器OK → ③传数据前[GL上限/地图/画布] →
   ④数据OK → ⑤算粗筛前 → ⑥算粗筛后 → ⑦就绪 → ⑧进帧循环 → ⑨遮罩已藏[画布/CSS/中心像素/出错码]`
   —— **停在哪一段、出错码是几，直接指向病因** ✓（排查时优先读 `readPixels` 的中心像素
   和 `getError()`：像素黑 = 真没画出来 ✗，像素有色却屏幕黑 = 显示/合成层的问题 ✓）

## 手机版怎么出
**桌面版和手机版共用同一套源码** ✓ 区别只有"打不打 `mobile/` 里那层补丁"：

```bash
python build_standalone.py     # 出桌面版 → pdx-map-editor.html
python mobile/build.py         # 出手机版 → pdx-map-editor-mobile.html
```

`mobile/` 里放着：

| 文件 | 是什么 |
|---|---|
| `mobile_css.txt` | 手机端样式，追加到 `web/style.css` 末尾 |
| `mobile_js.txt` | `bindMobile()`：一级六入口 + 二级下拉面板 + 触摸手势，插在 `bindEvents()` 前面 |
| `mobile_html.txt` | 启动页里那点注释（界面是 `bindMobile()` 运行时造的 ✓） |
| `patch.py` | 打补丁 / 退补丁（手动用才需要） |
| `build.py` | 一键：打补丁 → 烤单文件 → 改名 → **源码按字节还原** |

两个要点：

- `build.py` 开工前会拍**两个字节快照**（电脑版文件 + `web/` 三个源文件），收工原样写回。
  所以它**绝不会覆盖电脑版**，也不会弄丢你没提交的源码改动 ✓
- 手动 `python mobile/patch.py revert` 走的是 `git checkout`，所以要求那三个文件
  **没有未提交的改动** —— 有的话它会拒绝执行并提示你改用 `build.py` ✓

### 烤完记得验一遍

```bash
python build_standalone.py && node tools/check_standalone.js   # 电脑版：32 条
python mobile/build.py     && node tools/check_mobile.js       # 手机版：13 条
```

`check_mobile.js` 比电脑版那个多验两件事，都是手机版独有的坑：

- **补丁到底打进去没有**：`#mob-ui` 在 CSS 里、`function bindMobile` 在 JS 里、
  `bindMobile()` 那个启动挂点在不在、**而且只有一份**（重复打会叠一份 CSS ✗）；
- **打进去之后还跑不跑得起来**：补丁是在 `bindEvents()` 前面插一大段 + 在启动流程里插一句，
  锚点变了或者插歪了就是"一启动就抛、白屏" —— 它会真跑一遍 `boot()` 看能不能到「就绪」。

`mobile/` 那三块补丁**只碰界面**（造按钮、搬现成节点、接触摸手势），
内部函数只调通用的那几个（`actAt` / `setTool` / `setTier` …），
所以改 `app.js` 内部实现一般不影响它；但**锚点那条不能动**：
`function bindEvents() {` 和 `    bindEvents();` 各只能出现一次，`<footer class="statusbar">` 同理。

手机版的界面结构（改 UI 时先看这个）：

- **一级**：地图 + 顶栏（`←` 回主菜单 · 永夜廿九 · `↶ ↷` 撤销重做 · 教程 · 文件）+ 底部四个入口
  （设置 / 颜色 / 工具 / 视图；「工具」那个按钮上写的是**当前工具名**）
- **二级**：点某个入口 → 从**那个按钮正上方**弹出一栏（带指向按钮的小尖角；按钮在上半屏就往下弹）
- **设置**那一栏 = 一排标签（显示 / 颜色 / 边界 / 导出图例）+ 下面跟着换内容；
  高度在打开时按**最高那页**锁住 ✓ 切标签不跳
- **触摸**：单指按住拖动 = 连续涂色（自己驱动 `actAt`，不等浏览器的合成鼠标事件）；

  走之前会把涂色写进 localStorage 暂存（**按地图分开存**），再选同一张图会自动接上 ✓
